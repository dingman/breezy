# Plan: daily-budget day stop (operator ruling 2026-09-14 — "once it reaches the maximum, it stops trading for the rest of the day"; "fix it now")

Status: Rev 1 (code-architect), pending adversarial review (trading-bot-architect + security-reviewer). Base 3f2d96c. Refer to the operator controls only as "the daily budget" / "the per-position cap".

## §1 Nautilus L-1 native check — VERDICT: native halt is real but WRONG-SHAPED here; keep the durable marker

- `RiskEngine.set_trading_state(TradingState state)` is public (`.venv/lib/python3.13/site-packages/nautilus_trader/risk/engine.pyx:228`); `HALTED` denies every `SubmitOrder` at `engine.pyx:1134-1147` (`reason="TradingState.HALTED"`), enum at `nautilus_trader/model/enums.py:456-459`. Breezy ALREADY uses it natively — `/home/jon/breezy/src/breezy/runtime/account_presence_halt.py:171` — so this is proven reachable, at the **app composition root only** (`install_account_presence_halt` is called from `app/trade.py::_run_node` with the kernel's `risk_engine`).
- Disqualifiers, all three fatal for "stop for the rest of the *day*": (a) **not durable** — `engine.pyx:132` sets `TradingState.ACTIVE` at construction, nothing persists or restores it, so a relaunch at 20:00Z re-enables spending the exhausted budget; (b) **no re-enable at midnight** — there is no scheduler; un-halting needs a custom timer calling `set_trading_state(ACTIVE)`, i.e. MORE custom machinery than the marker, and one that can un-halt an `AccountPresenceHalt` halt it did not set (the two halts share one global state — a real collision, since that halt is explicitly "will not resume without an operator"); (c) **unreachable from the two sites that know** — the exec client (`adapters/`) and the strategy hold no `RiskEngine`, and reaching one would cross `adapters → runtime` (importlinter layers, `pyproject.toml:75-91`).
- Verdict: **custom day-keyed durable marker**, which the operator ruling's semantics (per-UTC-day, self-expiring, survives relaunch) match exactly. No Nautilus modification either way.

## §2 Chosen design

1. **Typed denial (removes text-matching).** `operator_controls.py:407-411` — raise a new `DailyBudgetExhausted(LiveTradingPermissionError)` at the daily-budget branch ONLY (clock-rewind at `:388-391` and the per-position branch at `:376-380` stay plain). `safety.py` session-budget branch (~929-1019) — new `SessionBudgetExhausted(LiveTradingPermissionError)`, **treated identically**: session notional *is* the daily budget (`safety.py:571-577 _derived_session_notional`), so its exhaustion is the same day's ceiling; the session order-count ceiling is budget-derived too and stops the day the same way. Message text unchanged (still names the control, never a value).
2. **Exec client writes the marker.** `exec/client.py:347-368` add `BUDGET_EXHAUSTED_KEY_PREFIX = f"{STATE_KEY_NAMESPACE}budget_exhausted/"`. Key: `exec/polymarket_us/budget_exhausted/<YYYY-MM-DD>` (UTC day from `utc_day_for_ns(now_ns)`, the ledger's own day function), value `b"1"`. Written in the two existing `except` arms — `:3000-3001` (permit) and `:3010-3011` (ledger) — by catching the typed subclass FIRST, writing via `self._store_set`, logging once, then falling through to the unchanged `self._deny(...)`. Same `SqliteStateStore` handle, same flock/namespace discipline; no delete needed — the key self-expires at UTC midnight.
   Log line (exec, once per day, guarded by a `_budget_marker_written: set[str]` process set): `budget stop: the day's spend ceiling is reached for 2026-09-14; no further orders will be authorized today` — no dollar figure, no env-var name.
3. **Strategy reads it.** `trial_day_latch.py` (after `is_family_halted`, ~:640) add:
   `def is_day_budget_exhausted(self, utc_day: str) -> bool` — `self._require_held()`, one `self._store.get(BUDGET_EXHAUSTED_KEY_PREFIX + utc_day)`, `raw is not None`. Exactly the `is_family_halted` shape. `continuous_strategy.py::_hunt_tick` — insert immediately AFTER the family-halt block (`:697-708`), BEFORE `is_consumed`/`attempt_state`/`is_inflight`: so it never touches IN_FLIGHT or the attempt counter and costs one store read on a path that already does several. Day = `utc_day_for_ns(snapshot.ts_event)` (UTC, not climate day — matches the ledger). Record `_DIAG_DAY_BUDGET_EXHAUSTED = "day_budget_exhausted"` (new constant beside `:97-103`), then `return`.
   Once-per-station-per-day via a new `self._budget_stop_notice: set[tuple[str, str]]` (beside `:299-305`, same pattern as `_rearm_decision_dedupe`), emitting ONE line + ONE alert:
   `budget_stop: KSFO/2026-09-14 not arming for the rest of the UTC day (the day's spend ceiling is reached)`
4. **Severity: WARN.** The alert is emitted by the STRATEGY (existing `_report_alerter` / `emit_alert` path) — the exec client may not import `breezy.runtime.health` (E0-TRANSPORT barrier, `client.py:3320-3323`). WARN not INFO because the node goes silent for hours and INFO is the level routinely filtered out of operator routing (`health.py:402 _LEVEL_FOR_SEVERITY`); WARN not ERROR/CRITICAL because nothing is broken — no `_refuse`, no `trading_refusals` entry, no `degrade()`.
5. **S0 seed (`_connect` / `_seed_spend_from_durable_fills`, `client.py:1257-1325`): do NOT derive the marker at seed time — write it only on an actual denial.** The ledger deliberately never exposes the budget to callers, so a seed-time derivation would need a second `operator_max_daily_budget_usd()` read outside the accessor (the exact thing `test_operator_control_assignment_scan` guards). Cost of denial-only: on a boot into an already-exhausted day, the FIRST armed tick submits, is denied, writes the marker — one denied order per relaunch, no money spent, marker set thereafter. Accepted.
6. **Layering:** strategy → adapters is the permitted downward direction (`pyproject.toml:75-91`); the read goes through `TrialDayLatch`, whose store+flock come from `SubmitIntentLatch.shared_state_binding()` via `open_trial_day_latch` (`trial_day_latch.py:945-962`) — no new binding, no new opener, adapters import nothing from runtime/strategy. Run `lint-imports` after the slice.

## §5 Risks

- **Marker on a transient non-budget denial** — closed by design: only the two typed subclasses mark; the clock-rewind branch shares the daily env-var name and is explicitly excluded (its own RED test). Residual: a future author adding a third raise in that branch without a subclass — mitigated by the exclusion tests, not by text matching.
- **Stale marker after an operator raises the budget mid-day** — real and accepted: the store has no delete and there is no automatic clear, so the day stays stopped until 00:00Z. This is the ruling's literal semantics ("stops trading for the rest of the day"); if a clear is ever wanted it should be a build-side CLI on the `breezy-clear-family-halt` pattern with an audit record, NOT an automatic re-read.
- **UTC-day vs climate-day skew** — a 00:00Z rollover lands mid-afternoon-LST for the western stations, re-enabling arming on a fresh budget mid-climate-day. Deliberate: the marker must roll exactly when the ledger's accumulator does (`utc_day_for_ns`), or the stop and the budget would disagree.
- **Multi-process** — the marker is written by the node's exec client and read by its strategy under the same flock; a study/replay process never writes it, and the backtest subclass reads `False` because no exec client exists.
