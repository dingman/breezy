## Scope
**In:**
- A native Nautilus `LiveClock` timer re-polls the two runtime surfaces whose handlers today fire only on `ComponentStateChanged`:
  - `install_reconciliation_refusal_alert` (`src/breezy/runtime/component_health_watch.py:265-319`)
  - `install_stale_intent_alert` (`:154-230`)
- This is the hunter finding routed to FU-8b (`docs/plans/backlog/FU-8_resolver_cross_session_fill_plan_r2_2026-09-26.md:141,162`). Today a runtime latch such as `resolver_fill_not_booked`, or an intent crossing the 15-minute staleness age (`client.py:569`), stays unalerted until some unrelated component changes state.
- The timer is armed in the composition root `_run_node` (`src/breezy/runtime/trade_cli.py:461-619`). Both handlers are already installed there (`:576-583`).

**Out (explicitly):**
- `install_component_degraded_alert` (`component_health_watch.py:322-396`). Its signal *is* the DEGRADED `ComponentStateChanged`, so polling adds nothing.
- The `current_rung_hold` secondary path (`composition.py:876-893`).
  - Its primary path already runs per tick (`:815-822`).
  - It is wired in `app/trade.py`, not `_run_node`.
  - Extending it is YAGNI until a gap is shown.
- The residual "boot mass-status raises → generic `_refuse`" (`FU-8 plan :151`). That is a boot-path attribution gap, not a delivery gap, and no timer fixes it. It stays a named residual.
- No synthetic `ComponentStateChanged` is ever published (`FU-8 plan :141`), because that would spoof a native event.
- No change to the exec client, the alert sink, `health.py`, any latch semantics, `allow_short`, operator caps or NO-SEND.

## L-1 null-hypothesis verdict
- **A native timer exists, so reuse it and do not build one.** Installed nautilus 1.231.0 provides:
  - `Clock.set_timer(name, interval, start_time, stop_time, callback, allow_past, fire_immediately)` (`nautilus_trader/common/component.pyx:419-482`).
  - `LiveClock.set_timer_ns`, which refuses a duplicate name via `Condition.not_in(name, self.timer_names)` (`:930-941`).
  - `cancel_timer` / `cancel_timers` (`:543-565`).
  - `TestClock.advance_time`, which returns `TimeEventHandler`s (`:790-836`); these fire through `.handle()` (`:1165-1169`).
- **Native lifecycle exists, so reuse it.**
  - `NautilusKernel.stop` and `stop_async` both call `_cancel_timers()` on the kernel clock (`system/kernel.py:1059,1100`). That logs `Canceled Timer(name=…)` for each timer (`:1443-1446`).
  - `kernel.dispose()` does **not** cancel clock timers (`:1108-1135`).
  - `TradingNode.run` catches `RuntimeError` and returns (`live/node.py:293-300`), so the kernel may never stop. The dispose path therefore needs an explicit cancel, and that cancel is the only lifecycle code built here.
- **Native periodic reconciliation is the wrong tool.**
  - `open_check_interval_secs` / `position_check_interval_secs` (`live/config.py:188,195`) re-run venue reconciliation, which is venue I/O. They do not re-read Breezy's in-memory refusal surfaces.
  - Enabling `position_check_interval_secs` is prohibited by standing ruling (execute-backlog 2026-09-12).
- **What genuinely does not exist:** a periodic trigger that joins the kernel clock to the two handler closures that are already returned. That join, plus a thread hop, is the entire build.
- **Thread fact that shapes the design (measured and pinned):**
  - A `LiveClock` callback runs on a Rust/tokio thread, not the asyncio loop thread (`tests/contract/test_live_timer_thread_affinity.py:7-12`).
  - The pyo3 wrapper calls the callback directly (`component.pyx:1006-1010`).
- **L-16:** a raise in that callback is silently discarded (`docs/core/LESSONS.md:772-819`; the "swallowed_and_the_timer_keeps_firing" test in `test_live_timer_thread_affinity.py`).

## Acceptance Criteria
1. **Arming.** `_run_node` arms exactly one timer named `REFUSAL_REPOLL_TIMER_NAME` on `node.kernel.clock`, with interval `REFUSAL_REPOLL_INTERVAL` (60 s). It arms only after `node.build()` has succeeded (after `assembled = True`, `trade_cli.py:562`) and both handlers are installed.
2. **Each fire.** Each timer fire runs the reconciliation-refusal handler and then the stale-intent handler, both **on the kernel event-loop thread**, via `loop.call_soon_threadsafe`.
3. **Runtime latch.** A reconciliation latch added at runtime (including `RESOLVER_FILL_NOT_BOOKED`) is alerted within ≤1 interval, with **no** `ComponentStateChanged` published.
4. **Runtime stale intent.** An intent that enters `stale_ambiguous_intent_alerts` at runtime is alerted within ≤1 interval, with no state-change event.
5. **Idempotence.** For any interleaving of the timer trigger and the state-change trigger, each `(latch, subject)` and each `intent_id` alerts exactly once. Both triggers call the same closure, so they share the existing dedupe sets (`component_health_watch.py:196,287`).
6. **The timer callback never raises.** This holds when the loop is closed, when `call_soon_threadsafe` raises, and for any `BaseException` from scheduling. A scheduling failure is logged at ERROR with exception **type only** (the `emit_alert` discipline, `health.py:681-699`).
7. **Handler failure.** A handler that raises inside the loop-thread poll is logged. It does not stop the other handler in the same tick, and it does not stop later ticks.
8. **Cancellation on every exit.** The timer is cancelled on every exit of `_run_node` that follows a successful arm: normal return, `node.run()` returning after swallowing a `RuntimeError` with the kernel never stopped, a raise from `run()`, and `KeyboardInterrupt`. Cancellation happens before `node.dispose()` and is idempotent alongside the kernel's own `_cancel_timers`.
9. **Arming failure is non-fatal but loud.**
   - It produces exactly `_report(stderr, "refusal re-poll timer NOT armed", exc, expected=False)`, which already logs at ERROR (`trade_cli.py:297-301`). No extra logger call is added.
   - The node still boots, and the state-change path is unchanged.
   - Rationale: this is informational delivery, not a control (FU-8 r2.1 ruling), and it must never cost a trading day (L-48 spirit).
10. **Build failure.** If `node.build()` raises, no timer is armed and no `NOT armed` line is written; the existing `trading node failed` path is unchanged.
11. **Positive arm signal (L-30).** A successful arm writes one INFO line, `refusal re-poll timer armed name=… interval_s=60`, through the `breezy` logger. The logging bridge is installed at `trade_cli.py:663`, before `_run_node` runs at `:710`.

## Edge Cases & NFRs
- **Premise: every `ComponentStateChanged` is published on the loop thread.**
  - Spot-checked: `continuous_strategy.stop` is called inside `on_start`, and the ingest actors hop to the loop before transitioning.
  - With this premise, the hop makes the timer trigger and the msgbus trigger mutually serial on one thread, so the dedupe sets need no lock.
  - If a future component published off-loop, that would be a pre-existing race independent of this change, and it is out of scope.
- **Armed before `node.run()`.**
  - The loop already exists: `TradingNode.__init__` obtains it (`live/node.py:65-79`), and `kernel.loop` returns `self._loop` (`kernel.py:654-663`).
  - `call_soon_threadsafe` on a not-yet-running loop queues the callback until `run_until_complete` (`node.py:298`).
  - This is measured by contract test 21, not assumed.
- **Fire during boot reconciliation.** The handler may read a partial latch set. This is safe because:
  - the latch dict is replaced copy-on-write (`client.py:3545-3548`);
  - dedupe covers later latches;
  - the post-reconciliation `ComponentStateChanged` still fires (`component_health_watch.py:273-278`).
- **Readers touch no store.**
  - Both readers return tuples of in-memory dict values (`client.py:1602-1614, 2019-2041`), so the thread-confined `_require_store` (`:4019`) is never reached.
  - The hop is still mandatory, because it serialises mutation of the dedupe sets with the msgbus trigger.
- **Stale-intent forget semantics are unchanged** (`component_health_watch.py:211-212`).
- **Timer firing after the loop is closed** (for example, a fire racing dispose):
  - `_on_timer` checks `loop.is_closed()` and returns silently.
  - The `is_closed()` check and `call_soon_threadsafe` can race, so a close landing between them yields **at most one** ERROR (type only), never a 60-second stream.
- **NFR cost:** per minute, two tuple copies of at most a handful of entries, plus set lookups. No I/O and no allocation growth (L-29; the sets are bounded by the latches).
- **Portability.** The module still names no venue (`test_exec_refusal_health_surface.py:710-725` stays green).
  - The `asyncio`, `Clock` and `TimeEvent` imports are type-only and go under the existing `if TYPE_CHECKING:` block (`component_health_watch.py:82`).
  - The only new runtime import is `from datetime import timedelta`.

## Design & Data Flow
**Flow:**
1. `_run_node` builds the node and installs both watches. It now captures the returned handler closures; today they are discarded at `trade_cli.py:576-583`.
2. `install_refusal_repoll_timer(clock=node.kernel.clock, loop=node.kernel.loop, handlers=(recon_h, stale_h))` calls `clock.set_timer(REFUSAL_REPOLL_TIMER_NAME, REFUSAL_REPOLL_INTERVAL, callback=_on_timer)`.
   - The handler order is reconciliation then stale. That is the reverse of the install order at `:576-583`. The difference is cosmetic, because the two handlers share no state.
3. **Each fire (tokio thread):** `_on_timer`, inside `try/except BaseException`, returns if the loop is closed. Otherwise it calls `loop.call_soon_threadsafe(_poll, event)`.
4. **On the loop thread:** `_poll` calls each handler inside `try/except Exception`, logging with `logger.exception`.
5. **Cancel:** the function returns an idempotent `cancel()`. It cancels the timer if the name is still in `clock.timer_names`, and swallows `KeyError`/`ValueError` at DEBUG.
6. **Dispose ordering:** `_run_node`'s `finally` calls `cancel()` (if set) before `node.dispose()`.

**Options considered:**
- **(A) Kernel-clock timer in the composition root. CHOSEN.**
  - It is the ruled site (`FU-8 plan :141`).
  - Kernel stop cancels it natively (`kernel.py:1059,1100`).
  - It needs no Actor, and `actors=[]` stays untouched.
- **(B) A dedicated Actor with `on_start`/`on_stop`, like `FeeDriftProbeActor` (`fee_drift_probe.py:248-277`). Rejected:**
  - (a) The module's own no-new-Actor rule forbids it (`component_health_watch.py:29-35`: `actors=[]` is a deliberate empty literal, and an Actor "would buy nothing"). It would also add an extra `ComponentStateChanged` source onto the very topic both handlers poll.
  - (b) The handlers are built after `build()`, but actors must be registered before it (`trade_cli.py:557-561`).
  - (c) An actor's clock has the same tokio-thread problem.
- **(C) Synthetic `ComponentStateChanged` publish.** Rejected by ruling: it spoofs a native event.
- **(D) Calling handlers directly in the timer callback. Rejected:**
  - the handler would run off-loop and race the msgbus trigger on the dedupe sets;
  - an uncaught raise would vanish (L-16).
- **(E) `kernel.loop.call_later` rescheduling itself. Rejected:**
  - no native kernel-stop cancel (`_cancel_timers` only knows clock timers, `kernel.py:1443-1446`);
  - no `Canceled Timer` line for the L-30 stop signal;
  - it bypasses the Nautilus-native timer that the project mandate says to prefer.
- **(F) Folding the re-poll into the exec client's resolver pass. Rejected:** the client may only record and may not import the alert layer (E0-TRANSPORT, `component_health_watch.py:233-236`), so this would add a cross-layer seam.

**Interval: `REFUSAL_REPOLL_INTERVAL: Final[timedelta] = timedelta(seconds=60)`.**
- The stale threshold is 15 minutes (`client.py:569`), so 60 s adds at most 6.7% latency.
- Surfaces change at most every resolver pass (5 s, `client.py:551`).
- Minute granularity is meaningful for an operator.
- The cost is negligible.

**`fire_immediately=False`:** the first post-boot read is already guaranteed by the post-reconciliation `ComponentStateChanged` (`component_health_watch.py:273-278`).
