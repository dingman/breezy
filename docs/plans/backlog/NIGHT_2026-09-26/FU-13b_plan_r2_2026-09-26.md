## Acceptance Criteria
1. **AC1 (09-13 evidenced, on a PROXY_LAG raw row).**
   - Given a snapshot holding REFERRAL_BONUS +25, TRANSFER +5 and ACCOUNT_DEPOSIT +10 in the 09-13 window, with no failure fields and a window tolerance of $0.00, the 09-13 row gets `external_flow_cents == 4000`, `unexplained_net == 0` exactly, and `net_classification == "EXPLAINED_EXTERNAL_FLOW"`.
   - Its raw `classification` stays `UNEXPLAINED_PROXY_LAG`.
   - `settled_cumulative_passes_net` is True when no other settled row breaches net.
2. **AC2 (never by inference).**
   - With no dir configured, or a snapshot that is absent, unreadable, malformed, stale for the window, incomplete for the window, or missing a flow, 09-13 is never EXPLAINED.
   - Without evidence, `net_classification` equals the raw label (today `UNEXPLAINED_PROXY_LAG`).
   - `external_flow_evidence_status ∈ {OK, INCOMPLETE, UNAVAILABLE, MALFORMED, NOT_CONFIGURED}` is **always** emitted.
   - Uncovered windows are counted in `n_windows_not_covered`.
3. **AC3 (no numeric drift).** Every pre-existing JSON key and value is byte-identical with and without a snapshot (golden test). The keys include `proceeds`, `capital_deployed`, `unexplained`, `classification`, `magnitude_cents`, `settled_cumulative_*`, `unexplained_flow_days`, `n_unexplained_*`, `roi*` and `realised_pnl_*`.
4. **AC4 (D7 schema).**
   - `PORTFOLIO_ROI_SCHEMA_VERSION` stays 3 (`:2027-2035`), and `_KNOWN_…` stays `{1,2,3}` (`:2045`). New keys are optional.
   - The reader surfaces absent keys as `None`, following the pattern at `:2727-2749`.
   - A present-but-wrong-typed `net_classification` (top level, or in `daily_reconciliation[i]`) raises `PortfolioRoiReportMalformedFieldError`. This matches the strict row reader at `:2143-2157`.
5. **AC5 (evidence required).** A flow is **counted** only if all of the following hold:
   - its type is one of the five flow types;
   - `status ∈ {COMPLETED, PENDING}` and `currency == USD`;
   - every failure field is empty or null (top-level and nested);
   - `createTime ∈ (prev_ts, this_ts]`.

   The window is **covered** only if `pulled_at_ns ≥ this_ts` and `covered_from_ns ≤ prev_ts`. EXPLAINED then needs a covered window, Σcounted ≠ 0, and `|unexplained − Σcounted| ≤ tolerance`.
6. **AC6 (the net ladder is defined for every raw label).** `_classify_net`:
   - BALANCE_UNKNOWN and NO_PRIOR_BALANCE pass through unchanged.
   - Not covered, or Σcounted == 0 with no unverifiable record: keep the raw label.
   - Any UNPARSEABLE, unknown-status, non-USD or **unrecognised activity type** record in the window gives `EXTERNAL_FLOW_UNVERIFIABLE`.
   - Otherwise `unexplained_net = unexplained − Σcounted`:
     - If it is within tolerance: `EXPLAINED_EXTERNAL_FLOW`.
     - Otherwise, re-run the raw proxy-lag ladder (`:1641-1655`) on `unexplained_net`: `UNEXPLAINED_PROXY_LAG` if there is a lag and the capacity is None or ≥ |net| − tol, else `EXTERNAL_FLOW_MISMATCH`.
   - A raw-OK window that contains a counted flow and has |net| > tol is MISMATCH, never OK.
7. **AC7 (reversal).**
   - A flow whose record, now or in any later snapshot, carries a failure or reversal marker is never counted.
   - Every window is recomputed from the newest valid snapshot on each run. So a later failure on the 09-13 deposit flips 09-13 from EXPLAINED to MISMATCH (|40 − 30| > 0).
   - An unrecognised reversal activity type makes its own window UNVERIFIABLE, and it is never dropped.
8. **AC8 (read-only venue path).**
   - The puller only issues `get_authenticated(..., quota_key=QUOTA_KEY_PORTFOLIO)` and is bounded by `MAX_PAGES`.
   - It imports no SDK (B5), nothing from `exec/`, and neither of the permit functions (B6/B7).

   - The literal `/v1/portfolio/activities` appears in exactly one module under `src/` and `scripts/`: `account_activity.py`. Today it appears in neither; `tests/` and `docs/evidence` are excluded.
9. **AC9 (no leakage).**
   - The snapshot stores `transaction_id_sha256` only. It never stores a raw id, `externalId`, `description`, `paymentMethod` or any balance. It is 0600 in a 0700 dir and written with O_EXCL.

## Edge Cases & NFRs
- **Deposit lag.** Flows are dated by `createTime`; `updateTime` can trail it by days (FU-3 `:19`) and is kept for diagnosis. A balance that moved in a different window gives a fail-safe MISMATCH, never EXPLAINED.
- **ADVANCED_DEPOSIT and PENDING.** Counted when there are no failure markers. A later failure un-counts the flow and flips the window (AC7). A failure status seen other than COMPLETED/PENDING is unknown, so the window is UNVERIFIABLE.
- **Withdrawals** (never observed live) are signed −|value| and flagged `sign_basis="type_table_unobserved"`. TRANSFER uses its literal sign; the +5 on 09-13 matches.
- **Shape drift (L-17).**
  - Use the top level first. Fall back to `transactions[0]` only if the top level is absent and there is exactly one nested entry. Otherwise the record is UNPARSEABLE and its window is UNVERIFIABLE.
  - An unparseable `createTime` means the window cannot be placed, so the whole snapshot is MALFORMED.
  - Unrecognised activity types are kept as `kind="UNRECOGNISED"` with timestamp and hash only, and no amount.
- **Types filter.** Fetch unfiltered (the `marketSlug` filter is inert, `.claude/skills/polymarket-us-integration/SKILL.md:334`). TRADE and POSITION_RESOLUTION are ignored because proceeds and capital already cover them.
- **Pagination.** Loop on `nextCursor` until `eof`, with `MAX_PAGES=20` and `limit=100`.
  - Hitting the cap gives INCOMPLETE with `covered_from = oldest createTime`.
  - At ≤12 requests/min (`transport.py:128`) this is under 2 minutes. `TimeoutStartSec=300` is pinned.
- **Venue 5xx or auth failure.** No file is written, the exit is non-zero, and `OnFailure=` alerts. The report falls back to the newest older valid snapshot, and coverage limits what it may explain.
- **Newest snapshot invalid.** `read_latest_snapshot` walks stamps newest-first and returns the first valid one. It records the rejected newer file's status in `newest_rejected_status` (JSON `external_flow_newest_rejected_status`).
- **Retention.** Keep all snapshots, with no prune code (and so no deletion path). Each file is a few KB and there is one per day.
- **Concurrency (L-50).** Files are immutable and written with O_EXCL; the report only reads.
- **Performance.** O(windows × flows) over tens of records.
