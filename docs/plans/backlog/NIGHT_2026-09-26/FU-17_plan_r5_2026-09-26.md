## Acceptance Criteria

**16. [r4→r5, ruling 1, REWRITTEN]** `_do_boot_retry` eligibility — the entry guard at the top of `_do_midday_watch` — is:

```
if (state.boot_zero_instruments_seen
    and not state.readiness_observed
    and state.first_boot_permit_expires_at_ns is None
    and not state.boot_retry_nontransient_alert_sent
    and not state.boot_retry_exhausted_alert_sent
    and (tracked_pid is None or (owned(tracked_pid) and node_log is not None))):
    return _do_boot_retry(...)
```

`owned(pid, *, process_alive)` is a new helper in `trade_supervisor.py`
(I/O-shell-adjacent, not a pure `DaySchedulerState` function — it reads
process state — so it lives beside `_retain_spawned_child`, not in `core.py`):

```
pid in _SUPERVISOR_SPAWNED and not (_SUPERVISOR_SPAWNED[pid].poll() is not None and process_alive(pid))
```

i.e. `pid` is a process this supervisor itself spawned, UNLESS our own
`Popen` shows it has exited while the OS-level pid is still alive (pid
reuse: whatever is now running at that pid is no longer ours, so treat it
as not-owned rather than falsely trusting a stale record).
`_SUPERVISOR_SPAWNED: dict[int, subprocess.Popen[bytes]]` is a NEW,
**never-popped** module-level dict — distinct from the existing, reaped
`_SPAWNED_CHILDREN` — filled unconditionally inside `_retain_spawned_child`
(`trade_supervisor.py:583-585`) alongside the existing
`_SPAWNED_CHILDREN[proc.pid] = proc` line. `_retain_spawned_child` is
already the ONE function every spawn site funnels through (`_do_launch`
`:1134`, `_do_relaunch_check` `:1210`, `_do_midday_watch` `:1372`, and
`_do_boot_retry`'s own new spawn), so this needs exactly one edit, not
three.

**`tracked_pid is None` arm — justified, not assumed:** after 17:10Z
(`SELF_CHECK_WINDOW_END_UTC`), `tracked_pid` can only be `None` as the
result of `_do_relaunch_check`'s decline (`trade_supervisor.py:1205`,
`return None, node_log, state`) — the only code path that clears it before
SELF_CHECK's window closes (`_do_relaunch_check` itself refuses to run at
all when `tracked_pid is None or node_log is None`, `:1153`, so it only
ever operates on — and un-sets — a genuine boot-spawned, logged child).
That decline is reached only after `ports.read_log_new(node_log)`
(`:1156`) has drained everything the shared `IncrementalLogReader`
(`:620-661`, offset logic `:637-655`) held for that log at that offset —
for a boot-spawned child whose log is read here for the first time, that
reader starts at byte 0, so any permit-issued line the child wrote before
dying was already latched via `record_permit_issued_seen`/
`record_first_boot_permit_seen` (`:1164-1169`) before the decline fires.
`tracked_pid is None` therefore never coincides with an unobserved
permit — `first_boot_permit_expires_at_ns` (already a separate, required
conjunct of this same guard) is the authoritative witness, and this arm
never reaches it by ignorance, only by genuine absence.

**17. [carried from r4, justification updated, not new logic]** Inside
`_do_boot_retry`, the (a)→(b) "no live child" transition is still an
EXPLICIT `ports.process_alive(tracked_pid)` check, never an inference from
`node_log is None`. Under the new eligibility rule this remains
structurally guaranteed unreachable-as-a-misread — whenever `_do_boot_retry`
is entered with `tracked_pid is not None`, AC16's guard already proves
`node_log is not None` — exactly the same relationship r4's
`boot_retry_adoption_seen` guard provided. **Verified not dead code:** this
`process_alive` call is the ordinary, always-exercised liveness check
driving every (a)→(b) decision on every dispatch, not a branch gated behind
a rare condition; only its "defense-in-depth" framing (guarding a
hypothetical future guard weakening) is unchanged from r4, not the code
itself.

## Hard-invariant cross-check (permit clamp)

**[r4→r5, ruling 4, restated honestly — no longer claimed for "every interleaving."]** The standing invariant — no boot-retry spawn may occur while a permit might exist that the supervisor has not observed — is satisfied for every state boot-retry itself can reach, via AC10/AC11/AC16 together, exactly as r4 argued (with `owned()`/`_SUPERVISOR_SPAWNED` now standing in for `boot_retry_adoption_seen`): the moment `tracked_pid` is a live, not-owned pid, or `node_log` is unknown, AC16 permanently disqualifies `_do_boot_retry` for that child and control falls to `_do_midday_watch`'s unmodified, already-safe body.

That proof is scoped to **this plan's own new code** (`_do_boot_retry`).
It does not, and cannot, close two residuals that are properties of the
EXISTING, unmodified system:

- **Security's argument (kept):** a supervisor restart zeroes `launch_done`
  (`initial_scheduler_state`, `_run_forever:1973`) — decision H's own,
  pre-existing non-goal — so `Phase.MIDDAY_WATCH`, and therefore this
  plan's `_do_boot_retry`, is structurally unreachable for the rest of a
  day following any restart past 17:00Z (the day re-enters `Phase.LAUNCH`/
  `RELAUNCH_CHECK` instead).
- **Architect's residual (kept, and independently VERIFIED, not just
  asserted):** a restart during 16:40-17:00Z, after a pre-restart child had
  already minted a permit and then died, leaves fresh in-memory state with
  `first_boot_permit_expires_at_ns=None`. `next_due` will return
  `Phase.LAUNCH` again, and `_do_launch` runs. If `probe_open_intent_state`
  finds an open intent, `decide_launch_action` returns
  `REFUSE_INTENT_OPEN` and nothing spawns — safe. If it does not (the
  ordinary case for a child that already resolved its own intents before
  dying), `_do_launch` proceeds to `ports.spawn(..., env=os.environ, ...)`
  — **verified directly against `trade_supervisor.py:1124-1126`: this call
  carries no `PERMIT_EXPIRY_CEILING_NS_ENV_VAR`, unlike `_do_midday_watch`'s
  clamped relaunch spawn at `:1369-1371`** — minting a second, fully
  unclamped permit while the pre-restart child's own permit may still be
  live or still expiring independently.

**Ruling:** this residual is **PRE-EXISTING**, not introduced or widened by
this plan. `_do_launch`'s spawn is unclamped in unmodified, pre-FU-17 code,
independent of anything boot-retry adds — and boot-retry's own unclamped
spawns (AC10) are reachable only from a wholly disjoint state (post-17:10Z,
zero-instruments, no permit ever observed), never via `_do_launch` running
a second time (LAUNCH only re-fires before `LAUNCH_WINDOW_END_UTC`=17:00Z;
boot-retry only starts at 17:10Z). Boot-retry therefore adds **no new
exposure class**. This is recorded as an accepted residual under decision
H (state-persistence non-goal), not folded into a claim that the invariant
holds in "every interleaving" — that overstatement is exactly what ruling
4 corrects.
