## Scope
**In scope (FU-13b).** Treat deposits, withdrawals, referral bonuses and transfers as a first-class input to the ROI report's cash identity. Every flow must be backed by evidence:
1. An unattended, read-only, signed `GET /v1/portfolio/activities` puller writes a closed-schema snapshot file. The snapshot is private (0600) and lives outside `docs/`.
2. `portfolio_roi_report.py` reads the newest snapshot and adds net-of-flow fields to each window and to the settled cumulative verdict. The fields are additive only.
3. A systemd unit and timer run the puller before the ROI report.

**Out of scope, explicitly:**
- Any change to `proceeds`, `capital_deployed`, `roi*`, `realised_pnl_*`, D9 or `trial_rows`.
- Any change to the meaning of existing JSON fields (`classification`, `unexplained`, `settled_cumulative_*`).
- The node, the exec client, `exec/`, permits, operator caps, `allow_short`, and live enablement.
- A heuristic flow-inference path.
- Kalshi.
- Parsing the free-text `description` field.

**Discrepancies in the brief:**

## L-1 null-hypothesis verdict
**The gap is real. Nautilus and the existing adapter both lack an external-flow source.**
- **Nautilus `AccountState`** carries only `account_id, account_type, base_currency, reported, balances, margins, info` (`nautilus_trader/model/events/account.pyx:58-77`). There is no reason or cash-flow type.
  - `__repr__` omits `info` (`account.pyx:91-101`), and that repr line is exactly what the report parses (`portfolio_roi_report.py:848-851`). So even a venue-populated `info` could never reach this reader.
- **Nautilus accounting** has no concept of a flow: a grep for `deposit|withdraw|transfer|ledger` under `nautilus_trader/accounting/` returns 0 matches.
- **`LiveExecutionClient`'s report surface** covers orders, fills, positions and mass status only (`live/execution_client.py:343,371,394,417,440`). There is no account-activity report.
- **The Breezy adapter's private read surface** is balances, positions and open orders (`adapters/polymarket_us/exec/endpoints.py:117-121`). Activities are absent.
- **The venue does expose flows.**
  - `Portfolio.activities` is a GET to `/v1/portfolio/activities` (`docs/evidence/venue/polymarket_us/sdk_snapshot/polymarket_us_0.1.2/resources/portfolio.py:23-29`).
  - `ActivityType` includes `ACCOUNT_DEPOSIT`, `ACCOUNT_ADVANCED_DEPOSIT`, `ACCOUNT_WITHDRAWAL`, `REFERRAL_BONUS` and `TRANSFER` (`types/portfolio.py:8-16`).
  - The live shape differs from the SDK TypedDict. The SDK declares `accountBalanceChange.transactions[]` only (`types/portfolio.py:79-92`). Captured payloads also carry top-level `status`, `amount{value,currency}`, `createTime` and `updateTime` (`AMBIGUOUS_ORDER_2026-09-05_SFO/activities_p0.json:18-58,61-97`). Per L-17, the parser must not trust the TypedDict.
- **Native extension point:** reuse the adapter's GET-only `PolymarketUSHttpClient.get_authenticated` (`adapters/polymarket_us/http.py:116-135`) and the shared factory wiring (`factories.py:518-530`), exactly as `set_family_halt_cli._default_live_positions_reader` does (`strategy/current_rung_hold/set_family_halt_cli.py:299-334`). No new transport and no SDK import.

## Acceptance Criteria
1. **AC1 (09-13 evidenced).**
   - Given a snapshot holding the three 09-13 flows (REFERRAL_BONUS +25, TRANSFER +5, ACCOUNT_DEPOSIT +10, per the FU-3 evidence `:11`), the 09-13 row gets:
     - `net_classification == "EXPLAINED_EXTERNAL_FLOW"`
     - `external_flow_cents == 4000`
     - `unexplained_net` within tolerance
   - `settled_cumulative_passes_net` becomes True if no other settled row breaches.
2. **AC2 (never by inference).**
   - With the snapshot absent, unreadable, malformed, stale (pulled before the window closed) or missing a flow, the 09-13 row's `net_classification` is never EXPLAINED.
   - `external_flow_evidence_status` names the cause (`UNAVAILABLE`, `MALFORMED`, `NOT_COVERED` or `INCOMPLETE`).
   - The same balance step with no evidence stays `UNEXPLAINED_CAPITAL_FLOW` in both `classification` and `net_classification`.
3. **AC3 (no numeric drift).**
   - For identical inputs, `proceeds`, `capital_deployed`, `unexplained`, `classification`, `magnitude_cents`, `settled_cumulative_unexplained`, `settled_cumulative_passes`, `unexplained_flow_days`, `n_unexplained_capital_flow_days`, `roi`, `roi_minus_b0`, `roi_minus_b1` and `realised_pnl_*` are byte-identical to pre-change output.
   - This holds with and without a snapshot, and is proved by a golden-comparison test.
4. **AC4 (schema policy D7).**
   - Every new JSON key is additive and optional. `PORTFOLIO_ROI_SCHEMA_VERSION` stays `3` (`portfolio_roi_report.py:2027-2035`) and `_KNOWN_PORTFOLIO_ROI_SCHEMA_VERSIONS` stays `{1,2,3}` (`:2045`).
   - `read_portfolio_roi_report` reads a v3 file without the new keys (they surface as `None`) and a file with them. This mirrors the optional-key pattern at `:2727-2749`.
   - No existing key changes meaning. Redefining `classification` or `settled_cumulative_passes` would be a semantic change needing a v4 bump; that is explicitly not done here.
5. **AC5 (evidence required).** EXPLAINED requires all of the following:
   - each contributing flow has `status ∈ {COMPLETED, PENDING}` and `currency == USD`;
   - each flow's `createTime` falls in `(prev_ts, this_ts]`;
   - the snapshot `pulled_at_ns >= this_ts`;
   - `abs(unexplained - Σ signed flows) <= tolerance`;
   - `Σ flows != 0`.
   Any unknown status, currency or type inside the window blocks EXPLAINED and gives `EXTERNAL_FLOW_UNVERIFIABLE`.
6. **AC6 (the net identity is honest both ways).** A window whose raw row is OK but which contains an evidenced flow gets `net_classification = EXTERNAL_FLOW_MISMATCH` when `abs(unexplained_net) > tolerance`. It is never silently OK.
7. **AC7 (read-only venue path).**
   - The puller issues GETs only, through `get_authenticated` with `quota_key=QUOTA_KEY_PORTFOLIO`.
   - Pagination is bounded by `MAX_PAGES`.
   - It imports no `polymarket_us` SDK (B5), nothing under `adapters/polymarket_us/exec`, and neither of `safety.issue_live_trading_permit` or `assert_live_order_submission_permitted` (B6/B7).
   - `find_execution_egress_modules()` output is unchanged (the N2 exact-set pin at `test_execution_egress_firewall_guard.py:737-772` is untouched).
   - `find_write_egress_violations` finds nothing in the new modules.
8. **AC8 (no leakage).**
   - The snapshot stores `transaction_id_sha256` only. It never stores a raw transaction id, `externalId`, `description`, `paymentMethod` or any balance.
   - It lives under `~/.local/share/breezy/derived/capital_flows/`, is 0600 in a 0700 directory, and is written with O_EXCL.
   - The puller's stdout carries only the status, page count, record count and path.
   - `journal_line` gains only dimensionless tokens, so the wrapper's currency-withhold regex (`portfolio-roi-run.sh:114`) never trips.
9. **AC9 (credential isolation).** The ROI unit still loads no `polymarket.env` (`tests/unit/test_portfolio_roi_deploy.py:40` stays green, unedited). Only the new puller unit loads venue credentials.
10. **AC10 (gate).** `scripts/ci/run_tests_no_egress.sh` passes in full, and `lint-imports` is clean.

## Edge Cases & NFRs
- **Deposit lag.** `updateTime` can trail `createTime` by days (FU-3 evidence `:19`), so flows are dated by `createTime`.
  - If the balance actually moved in a later window, both windows mismatch. The result is fail-safe (never EXPLAINED), and `updateTime` is recorded for diagnosis.
- **Withdrawal** was never observed live (L-17). It is signed −|value|, pinned by a synthetic test and flagged `sign_basis="type_table_unobserved"` in the snapshot.
- **TRANSFER direction** cannot be told from the type. The value's literal sign is used; the +5 on 09-13 matches exactly (FU-3 `:11`). A mis-signed transfer can only give a mismatch, never a false EXPLAINED, unless the balance moved by exactly the wrong-signed sum. That residual risk goes in the Risk Register.
- **Shape drift.** Use the top-level `accountBalanceChange.amount`/`status`/`createTime`. Fall back to the single nested `transactions[0]` only if the top level is absent and there is exactly one nested entry. Otherwise the record is `UNPARSEABLE` and its window is UNVERIFIABLE. An unparseable `createTime` makes the whole snapshot `MALFORMED`.
- **Types filter.** The server-side `types` filter is unverified, and the `marketSlug` filter is known inert (`.claude/skills/polymarket-us-integration/SKILL.md:334`). So: fetch unfiltered, then keep only the five flow types client-side. TRADE and POSITION_RESOLUTION are ignored because proceeds and capital already cover them.
- **Pagination.** Loop on `nextCursor` until `eof`, capped at `MAX_PAGES=20`, limit 100.
  - If the cap is hit without `eof`, the snapshot is `INCOMPLETE` with `covered_from = oldest createTime`. Windows before that are `NOT_COVERED`.
  - Worst case at 12 requests/min (`transport.py:128`) is under 2 minutes; `TimeoutStartSec` is pinned above the bound, following the fee-pull precedent.
- **Venue 5xx.** `/v1/account/balances` has returned 500/503 before (SKILL `:334`). If the pull fails, no snapshot is written and the unit exits non-zero with an alert via `alerts.env`. The report then uses the newest older snapshot, and coverage limits what it may explain.
- **Holes and opening days.** `BALANCE_UNKNOWN` and `NO_PRIOR_BALANCE` rows (`:1720-1750`, `:1688-1718`) get `net_classification = classification`. They are never EXPLAINED because their `unexplained` is None.
- **Multiple flows in one window** are summed. Duplicates across pages are de-duplicated by `transaction_id_sha256`.
- **Concurrency (L-50).** The puller writes one immutable file per run, and the report only reads. There is no shared rewrite-in-place file.
- **Performance.** The report does an O(windows × flows) scan over tens of records, which is negligible.

## Design & Data Flow
**Today:**
- `_run` reads `breezy-trade-*.log` `AccountState(` lines (`:3589-3605`), plus the G1 look-back (`:3614-3629`).
- `reconcile_daily` computes `unexplained = delta - proceeds + capital_deployed` (`:1633`) and classifies at `:1639-1657`.
- `cumulative_reconciliation` gates `abs(Σ) <= Σtol` (`:1894`).

**Options:**

| Option | Verdict | Why |
|---|---|---|
| A. Read-only venue activities pull, stored as evidence | **Chosen** (its output is B's ledger, populated automatically) | Venue-authoritative, per-transaction and timestamped. It reuses the adapter's GET-only client. It was already proven by hand once (FU-3 E2, 1 request, 32 activities). |
| B. Operator-declared ledger file | Rejected as a manual input | The operator may only set the two caps. It survives only as A's automatically written snapshot. |
| C. Infer flows from balance steps with no trades | Rejected as evidence | Circular: it would "explain" any unexplained step, including a real accounting bug (for example FU-3b's missing payout). It is already covered honestly by the `UNEXPLAINED_CAPITAL_FLOW` label. |
| A′. Pull activities from inside the node or exec client | Rejected | Widens the live process and `exec/` (a new N2 pin row). The ROI report needs daily evidence, not node state. |

**Schema decision.**
- **Chosen: v3-additive.** The existing `classification` and `settled_cumulative_passes` keep their D4 meaning, a raw cash identity with no flow term. The new `net_classification`, `unexplained_net`, `settled_cumulative_unexplained_net` and `settled_cumulative_passes_net` carry the verdict with evidenced flows applied.
- The Markdown headline and `journal_line` show the net verdict first and the raw one beside it.
- **Rejected alternative:** add the flow term to the D4 identity itself and bump to v4. It is cleaner semantically, but it changes the meaning of five existing fields and every historical comparison. This is flagged as the top peer-review question.

**Flow:**
1. **Puller** (timer 17:25Z, before the ROI run at 17:40Z per `docs/core/PROGRESS.md:68`):
   - `config_from_env` → `shared_polymarket_us_http_client` → paged `get_authenticated`.
   - `account_activity.parse_external_flows(page)` returns a tuple of `ExternalCapitalFlow`.
   - `external_capital_flows.write_snapshot(...)` writes `PRIVATE_capital_flows_<UTCstamp>.json`.
2. **Report:**
   - `_load_external_flow_evidence(dir, now_ns)` returns `ExternalFlowEvidence(status, flows, pulled_at_ns, covered_from_ns, sha256)`.
   - `reconcile_daily(..., external_flows=evidence)` computes the per-row net fields using a new pure `_classify_net`.
   - `cumulative_reconciliation` adds the net sums.
   - The builder, JSON, Markdown and journal are then updated.

**Firewall fit:**
- `account_activity.py` sits under `src/breezy/adapters/polymarket_us/`. It is venue-touching (C1, readonly guard `:37`), so V1-V5 apply (`:84-104`). It is outside `exec/`, so there is no E0 row (`firewall_guard.py:180-183`). Its basename is not in E1 (`:186-198`), and it defines no E2 class and no E3 verb, so the N2 pin is unchanged.
- The puller is venue-touching via C2 (`scripts/venue/`), with the same result.
- The literal `/v1/portfolio/activities` does not match V2's `/v\d+/orders?`.
- The puller is the only module that may call the path. This is pinned by a new exact-set test (L-12 style: one row).
