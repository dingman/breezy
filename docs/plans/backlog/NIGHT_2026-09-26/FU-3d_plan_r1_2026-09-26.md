## FU-3d Plan r1: the scored path is qty-1 by construction, so enforce that instead of scaling; also measure the fee_unverified bias

**Headline:** the premise behind "scale the scored path" does not hold. The live scorer excludes every fill with qty≠1 before it calls `score_trial`, so no `ScoredTrial` row can carry qty>1. The plan below therefore **rejects scaling `pnl`**. Instead it turns that construction invariant into a check at the store boundary, fixes the report label, and measures the fee_unverified bias. It also found that the "≤1¢ per contract" bias bound is **false in general**: the fee can reach 2¢ per contract.

## Scope
- **In:**
  - (a) Prove and enforce, at the only writer of the ScoredTrial store, that every persisted row is a qty==1 fill. That makes `ScoredTrial.pnl` per-contract and per-fill at the same time.
  - (b) Replace the report's "scored P&L is per-contract until FU-3d" label with the proven statement.
  - (c) Track the fee_unverified residual bias as a **modelled** figure in the portfolio ROI report, never as a correction to P&L.
  - (d) Close the PROGRESS row with its supersession note.
- **Out:**
  - Scaling `ScoredTrial.pnl` by qty (Option A, rejected below).
  - Adding a `qty` column to `SCORED_TRIAL_SCHEMA` (Option B). This is deferred to the R-11 / L-40 "Increment B" qty>1 PREREG ruling, which has to re-validate the boundary artefact anyway.
  - Paper-replay ROI (`current_rung_hold_paper_replay.py:1454`), which is in memory only and never persisted.
  - Rewriting any stored row.

## L-1 null-hypothesis verdict
- Nautilus `Position.calculate_pnl` (`.venv/.../nautilus_trader/model/position.pyx:780-810`) and `realized_pnl` (:668-669) are qty-scaled, but they only account for **closing fills**. Venue settlement (POSITION_RESOLUTION) is not a Nautilus fill, so no native path books a settled binary payout.
- The ScoredTrial store itself is already an accepted genuine gap (`scored_trial_store.py:12-15`).
- Verdict: nothing native applies, and this plan adds no infrastructure. It adds one guard, one label and one disclosure figure, all in existing modules.

## Edge Cases & NFRs
- **`qty ≤ 0`:** already refused as `malformed_input` by `_validate_qty` (:360-372) before `_admit_fill`, so it never reaches the guard.
- **qty>1 and partial fills:** routed to `multi_fill`/`partial_fill` residuals (:402-412). They are already in `RESIDUAL_EXCLUSION_REASONS` (`residual_fills.py:79-89`), so FU-3c's residual path (`portfolio_roi_report.py:1091-1095`) already qty-scales their payout and P&L. **This is where the qty>1 P&L lives today, and it is already correct.**
- **Duplicate fills:** `duplicate_fill` carries its own qty (`score_live_trials.py:877-891`) and is also residual, so it is unaffected.
- **Fee model:** `fees.py:596-605` rounds banker's-style per fill and warns of error in both directions. AC4 is therefore labelled "modelled", never a bound.
  - At θ=0.0695, `θ·p(1−p)` peaks at 0.017375 (p=0.5) and rounds to **0.02**.
  - The fee is ≥1.5¢ for p∈[~0.33, ~0.67], so the FU-3c "≤1¢/contract" claim (FU-3c plan :25, :87, :113) holds only outside that band. CFJ485874TMM at 0.70 gives 0.0146 → 0.01.
- **θ unresolved:** `taker_fee_at_fill` returns `None` when no θ as-of is pinned (:583-584). That row is counted in a third field, `n_residual_fee_unverified_unmodelled`, and never coerced to 0.
- **NFR:** read-only, no egress, no new I/O beyond what `enumerate_family_station_pairs` already returns (`fee_reconciled_by_trial_id`, :2992, :3047-3056).

**Options:**
- **A. Scale `pnl` in `score_trial` by `qty` (rejected).**
  - It is an L-2 unit change on a registered statistic.
  - It breaks the ROI-bound ratio, the payout identity and the monitor contract.
  - It requires editing the per-contract fee test (:226), which would weaken a contract test.
  - It fixes nothing: no scored row can have qty≠1.
- **B. Additive nullable `qty` column plus a consumer-side `position_pnl` (deferred).**
  - Correct shape for the future, but it activates two dormant PREREG guards and ripples through the schema-drift check and pins.
  - It is YAGNI until qty>1 is admitted, and admitting qty>1 is itself gated by an L-40 re-validation ruling. It belongs to that ruling's plan.
- **C. Enforce the qty≡1 invariant at the writer, fix the label, track the fee bias (chosen).**
  - Zero change to any stored or registered number.
  - Makes "per-contract == per-fill" a checked fact instead of an assumption spread across the ~10 consumers above.

**Flow after the change:** state-DB fills → `_validate_qty` → `_admit_fill` (qty≠1 goes to residual) → **new guard** (qty==1 else raise) → `score_trials` → `write_scored_trials`. In the report: residuals whose `fee_reconciled` is False → `taker_fee_at_fill` → AC4 fields → markdown disclosure.
