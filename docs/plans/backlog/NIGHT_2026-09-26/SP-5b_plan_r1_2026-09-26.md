## Plan: SP-5b — INDETERMINATE exclusion of dead-recorder gap rows (prospective)

## Scope
**In**
- A new optional family-manifest key, `coverage_indeterminate_exclusion`. It accepts only the literal JSON `true`. If absent it means OFF, which is the state of every existing family.
- When the flag is ON, `covered_listed_station_days` classes a station-day INDETERMINATE if its afternoon overlaps a never-resolved `QuoteTapeGap` from a recorder instance that is no longer running. The day is excluded: it is not covered and not not-covered. The exclusion is logged to stderr for each station-day.
- One behaviour-preserving extraction, so the counter reuses the ingest CLI's existing instance-death rule rather than keeping a second copy of it.
- A pin test that names the manifests registered before this ruling. None of them may ever carry the key (prospective only).

**Out (the ruling rejects these or does not order them)**
- Any duration tolerance. The 60 s rule is rejected (ruling "Contradiction" bullet 1).
- Any inferred close time for a dead instance, i.e. (iv-b). That needs its own ruling (ruling ADOPTED #5).
- Any change to any-overlap, `[12:00,17:00)`, 30 min, or ≥15 (ruling ADOPTED #3).
- The six-key `--output` JSON. It is pinned: `structural_dead_stop.py:187-189` and shell greps in `score-live-trials-run.sh:218-231,258-305`.
- Changes to shell wrappers or units, to the tape, or to `resolved_gaps_by_seq`.
- Turning the flag on for any family.

**Finding for the coordinator (verified against the code)**
- The counter's only output is the *covered* count (`structural_dead_stop.py:192-216`). No consumer uses a listed or not-covered denominator. `structural_dead` reads only `covered_listed_station_days >= 15` (`:121-126`), and the tally markdown prints only the covered count (`family_tally_v2.py:1414-1422`).
- A zombie day already adds 0 today, through the `continue` at `:207`. So INDETERMINATE exclusion **cannot change `count` in either direction**, flag ON or OFF.
- What it changes is the per-day classification and the audit log. That is exactly what the ruling orders, and it satisfies ADOPTED #2 ("delay, never manufacture") by construction.
- Under L-38 it does **not** make the KILL clock more able to increment. PROGRESS must not claim that it does.

## L-1 null-hypothesis verdict
- Nautilus assigns each node a `UUID4` `instance_id` (`.venv/.../nautilus_trader/system/kernel.py:160`; config `system/config.py:107`). It streams to `{catalog_path}/{environment}/{instance_id}` (`kernel.py:588`), which gives `live/<id>/`.
- Nautilus has no notion of whether a past instance's process is still alive. Liveness is a systemd fact.
- Breezy already owns the sanctioned predicate: `take_liveness_snapshot` (`src/breezy/runtime/quote_tape_ingest_cli.py:1602-1633`) and `instance_is_dead = not (instance_id == newest_instance_id and service_active)` (`:1699`), built on native directory layout plus `systemctl --user is-active` (`:852-869`).
- **Verdict:** the gap is real only at the counter. The plan reuses the existing snapshot and builds no new liveness mechanism. Manifest opt-in follows the `no_leg_exit` precedent (`family_manifest.py:363-371`).

## Acceptance Criteria
1. With the flag ON, a listed station-day whose afternoon overlaps a collapsed row with `resolved=False`, from an instance that is dead per AC-5, is not counted as covered.
2. With the flag ON, that day emits no `not covered` stderr line. It emits exactly one `INDETERMINATE excluded` line naming city, day, `recorder_instance_id` and `gap_seq`. The depth loader is never called for it.
3. With the flag ON, one closing summary line reads `indeterminate-excluded station-days: N of M listed`.
4. With the flag OFF (no manifest, or a manifest without the key):
   - count, stdout, stderr bytes and output JSON bytes are identical to pre-change behaviour;
   - `take_liveness_snapshot` is never called, so no systemctl call is made.
5. An instance is dead iff it is in `snapshot.instance_ids` and `snapshot.instance_is_dead(id)`. An open row whose instance is missing from the inventory, or is the current instance while the service is active, keeps today's not-covered behaviour.
6. If the liveness snapshot raises `PreflightError` or `OSError`:
   - classification is disabled for that run, with one stderr line;
   - the count is unchanged;
   - exit status stays 0, so the champion counter is never dropped.
7. For every input fixture, the flag-ON count equals the flag-OFF count (the delay-never-manufacture invariant, checked on a zombie fixture, a mixed fixture and a clean fixture).
8. A resolved row, or an open row from a live instance, on a day that also has a dead-instance open row still yields INDETERMINATE: exclusion dominates.
9. Afternoon depth recorded by a later instance never rescues an INDETERMINATE day. This proves no close-time inference.
10. Manifest loading:
    - `"coverage_indeterminate_exclusion": true` loads as `True`, and absent loads as `False`;
    - `false`, `1` or `"true"` are refused with a message to omit the key instead;
    - `dump_family_manifest` omits the key when it is `False`;
    - every committed manifest's `manifest_sha256` is unchanged.
11. An exact-set pin test lists the pre-ruling manifests: `pm_us_crh_v2`, `pm_us_crh_v4`, `pm_us_crh_cont`, `pm_us_crh_exit_v4`, `kalshi_crh_v1`. None may carry the key. It also checks that the set of flag-bearing manifests in `deploy/families/` equals `frozenset()` today, and can only be widened by one reviewed row (L-12).
12. `run_ingest` behaviour is unchanged after the refactor to `LivenessSnapshot.instance_is_dead`, and the whole existing ingest suite stays green.
13. The full gate `scripts/ci/run_tests_no_egress.sh`, plus ruff, mypy and `lint-imports`, are all green.

## Edge Cases & NFRs
- The same zombie row on another station-day is ignored, because `_gap_applies_to` scopes by the day token (`:144-145`). Instrument ids are day-specific (ruling, measured facts).
- An open row that starts at or after 17:00 LST does not overlap, per `_gap_overlaps_afternoon` (`:158-160`), so it is not INDETERMINATE and the day follows the normal path.
- `live/` is missing, for example in a work-catalog copy: covered by AC-6 (fail-closed, count unchanged).
- The newest instance with the service inactive counts as dead, consistent with ingest `:1699`.
- Performance: the snapshot is taken once per run, and only when the flag is ON. It is O(instances) mtime stats, identical to the ingest timer's cost.
- Determinism: the classification depends on host state at run time. That is acceptable because the count is invariant (AC-7), and the log records the snapshot's `newest_instance_id` and `service_active`.
- Tests never call the real systemctl. The probe is injected, following the existing `service_active_probe` parameter at `:1607`.

## Design & Data Flow
The flow is:
1. `main` reads `manifest.coverage_indeterminate_exclusion`. With no manifest the flag is `False`.
2. It calls `count_covered_listed_station_days_from_catalog(..., indeterminate_exclusion=flag, service_active_probe=default)`.
3. If the flag is ON, that call builds `dead_ids` from `take_liveness_snapshot(catalog_root, DEFAULT_SUBDIRECTORY)`.
4. It passes `covered_listed_station_days(..., dead_recorder_instance_ids=dead_ids | None)`.
5. `None` takes the legacy path unchanged.

Options considered:
- **(A, chosen) Manifest key plus reuse of the ingest liveness snapshot.** The manifest is the registration artefact, the loader is already exact-set, and the key flows through both existing counter invocations with no wrapper edit (`score-live-trials-run.sh:203-206,252-255`).
- **(B) New CLI flag in the wrapper.** Rejected. The flag would sit in a shell script rather than the registration, which violates ADOPTED #4 ("recorded in their registration").
- **(C) Treat every instance in the catalog as dead** (ingest only lands dead instances). Rejected. Since GL-14 per-file conversion, a live instance's rotated files do land (`quote_tape_ingest_cli.py:112-129`), so the premise is false.
- **(D) Re-implement the "newest and active" rule inside the counter.** Rejected as a second copy of the policy. Instead, a method on `LivenessSnapshot` is used at `:1699`.
- **(E) Add an `indeterminate_excluded` key to the output JSON.** Rejected, because it breaks the six-key contract. Stderr is the established observability channel (`:187-189`).
