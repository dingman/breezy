## 9. Validation: failure cases, integration, autonomous operation
- **19a, caller omits `family_id`** → `TypeError` at the call site, uncaught, non-zero exit; no row is built. Fail-closed by construction (D1), not by a runtime check that could be skipped.
- **19a, a malformed `family_id`** (empty, containing `/`, or `..`) → refused at the builder before any id is formed, so a path-shaped segment can never widen or escape the namespace.
- **19a, layering:** `paper_replay.py` lives in `breezy.runtime`; it gains **no new import** (`family_id` arrives as a plain `str` argument). Had it needed the manifest type, `runtime → persistence` is a legal downward edge under the `layers` contract (`pyproject.toml:71-92`, `runtime` above `persistence | registry | normalize`), already exercised by `runtime/node_config.py:92`'s `from breezy.persistence.family_manifest import FamilyManifest`. `lint-imports` is run regardless (step 15).
- **19a, live-path impact: none.** `paper_replay.py`'s id builder is reachable only from `filled_trials_from_engine`, whose only argument is a `BacktestEngine` — a backtest-only object; its two callers are `current_rung_hold_paper_replay.py` and (via `run_one_precision_arm`) `whole_tape_paper_replay.py`, both offline analysis scripts. No live trade node, wrapper or unit imports it, and the live id space (`current_rung_hold/trial/`, `live_family_tally.py:83`) is not touched. The live node's behaviour is unchanged.
- **19b, manifest missing / unreadable / malformed JSON** → `FamilyManifestValidationError` or `OSError`, uncaught, non-zero exit. A scheduled caller records a BLOCKED run; it never proceeds on defaults.
- **19b, manifest registers a θ the config rejects** → `CurrentRungHoldConfig.__post_init__` is the second line of defence; `family_manifest.py:300-310` already bounds θ to `(0, 1)`. No new validation is invented.
- **19b, both the flag and a conflicting `--strategy`** → refuses (A5). A silent preference here would manufacture a row describing a family nobody armed — the exact failure mode of memory `bss-headline-is-the-wrong-family`.
- **Integration:** with the flag absent, AUD-09's runner is unaffected by 19b and cannot break `whole_tape_paper_replay.py`. 19a does change what AUD-09's parquet rows carry as `trial_id`; per ruling item 8 (`:200-203`) AUD-09b may build and run before 19a with a one-line caveat, and after 19a its rows become family-scoped with no code change on its side (the id is built inside the driver AUD-09 spawns). **Its parameter-provenance fields do NOT follow from 19b alone, and this plan previously claimed otherwise — the claim is withdrawn.** AUD-09 §6b.2 item 3 (`AUD-09-scheduled-per-station-replay.md:498-509`) has its runner call `load_family_manifest` itself and stamp `engine_required_fee_coefficient` from the driver's class default; it neither passes `--family-manifest` nor reads a sidecar, so `params_match` would stay `False` forever. AUD-09's document is not edited; the wiring is **AUD-19c** (§6), owned here and sequenced behind AUD-09b's runner.
- **19b, a stale sidecar from a previous run into the same `--output-dir`** → impossible: C6 step 1 unlinks it before the engine starts, unconditionally. A crashed or flagless run therefore presents **no** sidecar rather than a predecessor's, and C6 step 2's `argv_sha256` makes even a hand-placed file unmatchable.
- **19c, sidecar missing or `argv_sha256` mismatched** → `record_blocked`, day stays queued, exit 0 (E3). Never a `DRIVER_DEFAULTS` row, which after 19c could only be a misattribution.
- **19c, the driver subprocess dies abnormally (signal, OOM-kill in the unit's own cgroup, segfault)** → the runner survives its child and appends one `outcome="FAILED"` row carrying `UNCLASSIFIED_DRIVER_EXIT_<returncode>`, exits non-zero, and the day leaves the queue (D6, §6 E3) — AUD-09 §6b.3 `:655-657`'s rule for a crashed engine run, applied unchanged. Loud (failed unit, §9 `:923-928`), fail-closed (a row always exists, so the day is never silently re-queued forever), and never a silent drop (the row names the returncode, so the crash class is diagnosable from `replay_results.jsonl` alone).
- **19c, AUD-09b's runner does not exist yet** → 19c simply does not start; 19a and 19b stand alone and nothing is left half-wired, because with the flag unpassed the driver's behaviour is exactly A2's.
- **Autonomous operation:** the driver is invoked by a scheduler (AUD-09), never interactively. Every failure mode above is a loud non-zero exit with a message naming the conflicting values — no state to recover, no retry logic to get wrong, and no partial or stale write (pre-run clear, then `os.replace` from a temp file, C6). A refusal is self-describing in the caller's captured stderr, and after 19c it is a `BLOCKED` row rather than a silently-defaulted one.
- **Citability, unchanged:** a replay row stays non-citable under PREREG v3 §9 regardless — ruling Q2 (`:22`, `:270-277`), permanently and live-venue-only. This item changes what a row *proves about its own identity and parameters*, never whether the row may be cited.
