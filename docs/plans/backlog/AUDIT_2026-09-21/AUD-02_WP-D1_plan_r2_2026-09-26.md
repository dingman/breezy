## Venue pull
**Timer.** `OnCalendar=*-*-* 16:52:00 UTC`. This tick is free: it is not a 15-minute tick and not 17:15 or 17:25.

**Behaviour.**
1. Read the node unit's journal (`journalctl --user -o json`), polling every 10 s, until the first initial summary after 16:35Z. The deadline is 17:12Z.
2. On the deadline, write `no_pull.json` and exit 0.
3. Once the summary appears, build the provider from the node's discovery config with a public-only client.
4. Page `get_public(MARKET_LIST_PATH, query=provider._query(offset))` until a short page. Reaching `MAX_DISCOVERY_PAGES` means INCOMPLETE. Store the raw pages.
5. For each slug in N but not in V, GET `MARKET_BY_SLUG_PATH`.
6. Record `pull_start`, `pull_end` and the paired line's timestamp. Make one attempt and do not retry.

**Unit.** oneshot, `breezy-studies.slice`, MemoryHigh 128M / MemoryMax 256M, `Nice=10`, `OnFailure=breezy-study-failed@%n.service`. It shares no state with the node.

## r3 (2026-09-26): node evidence moves from journald to the node LOG FILES
**What Stage 0 found.**
- **The node never reaches journald.** `spawn_node` (`trade_supervisor.py:711-738`) uses Popen and sends stdout to `~/.local/share/breezy/logs/breezy-trade-<ts>.log`, one file per spawn. [N11] bans any systemd unit for the node.
- **The journal's discovery lines come from the RECORDER,** which is a different process and a different set.
- **The three lines exist in the real node files** (55 files, 09-04..09-25):
  - the count line (`BREEZY-L001.POLYMARKET_US-discovery`);
  - the summary (`…DataClient-POLYMARKET_US`, from `data.py:1326-1330`);
  - per-slug subscribing (`:1318`).
- **Format.** ANSI-wrapped, UTC, nanosecond precision: `2026-09-23T16:50:50.404256598Z [INFO] <component>: <msg>`.
- **Cycle timing.** The initial cycle runs at about 16:50:50Z, and reloads run about every 6h.
- **The count balances** (count = initial + reloads) in every file that has a summary. On 09-10 there is one surplus count line, which is the raised cycle at 14:00Z (a `:1262` ERROR).
- **Days with no summary:**
  - 09-07 and 09-25: "resolved 0 instruments; refusing to start".
  - 09-18: a relaunch storm that died mid-subscribe.
  - 09-05: 13 relaunch files.

**Amended AC2 (replay source).**
- The replay unit is the log FILE, replacing `_PID`. The glob is `breezy-trade-[0-9]*T*Z.log`, which excludes supervisor logs.
- A file belongs to a day by its line timestamps inside the window, never by its filename.
- Replay from the file's own `initial` summary, then slice to the window.
- Parsing: strip ANSI, match `^(\d{4}-\d\d-\d\dT[\d:]{8}\.\d{9})Z \[(\w+)\] (\S+): (.*)$`, keep integer nanoseconds, and `literal_eval` the payloads.

**Amended AC4 (pairing).**
- All timestamps come from the lines themselves, compared against `pull_start`/`pull_end` from `time.time_ns()`.
- P is the latest summary across in-scope files.
- An interleaved attempt means any of: a count line, a `:1262` ERROR, or a new file's first line appearing between P and `pull_start`.
- The 600 s and 120 s limits are unchanged.

**Amended AC6 (errors).**
- ERRORs are counted over in-scope Nautilus lines, both filtered and unfiltered.
- Unprefixed stderr lines (`configuration error`, `Traceback`) are counted separately and are never whitelisted.
- A count line with no summary is a raised cycle.

**Amended AC7 (eligibility).**
- `NODE-DOWN`: no in-scope file.
- `RELAUNCH-FAILED`: no `initial` summary by 17:12Z in any file created at or after 16:35Z.
- `REPLAY-GAP` (the journald-suppression trigger is removed) when any of these holds:
  - (a) the file starts mid-process, i.e. its first discovery line is a reload or an orphan count;
  - (b) the file is truncated or has an unparseable or cut line;
  - (c) there are count and slug lines but no `initial` summary;
  - (d) any of the r2 triggers.
- Multi-spawn days: replay each file separately; N comes from the file containing P.
- `PULL-INTERLEAVED-RELAUNCH`: a newer spawn appears in `(ts(P), pull_end]`.

**Pull trigger (replaces the journalctl read).** Every 10 s:
1. Re-glob and keep files with mtime ≥ 16:35Z.
2. Follow each file from byte 0 with a per-file offset.
3. Trigger on the first `initial` summary at or after 16:35Z in the newest-created file.
4. If a file shrinks, reset its offset and record `truncated=true`.
5. Record the path, inode and offset in `pull.json`.
