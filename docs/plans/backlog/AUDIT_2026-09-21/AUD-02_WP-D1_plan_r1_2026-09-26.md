## Findings
- **No `discovery_set_equality.py` exists yet.**
- **The node logs only counts per discovery cycle, never slugs.** `provider.py:602-606` prints "loaded N active … discovered K total". There is therefore nothing to check set equality against. - **Discovery runs are event-driven, not on a fixed poll.** `_discover_markets` (`provider.py:668-709`) pages `/v1/markets` and filters with `_weather_market_payloads(payload, city_codes)`. Reloads happen at venue endDate boundaries (`quote_tape_cli.py:263-268`).

## Acceptance criteria
1. **Closing rule committed first.** The note `docs/evidence/WP-D1_discovery_set_equality_<date>.md` carries a dated closing-rule header, committed before any data is read. It restates plan rules 1–4 and Rev 2.1 item 3.
2. **Per-day outputs.** The script runs offline on two inputs: a stored venue list (full pages) and a node journal export. For each day it reports:
   - the `venue_only` and `node_only` slug sets;
   - ERROR counts, both filtered and unfiltered. The filter is the regex `\bERROR\b.*(discover|provider|listing|instrument)` with a whitelist for the `BREEZY-NWS subscribe` error.
   - an eligibility flag. A day with no discovery cycle is INELIGIBLE.
   - a verdict. SUPERSEDED-BY AUD-08a requires ≥5 eligible days, each with equal sets and 0 non-whitelisted ERRORs. Anything else is FIX-SLICE.
3. **Venue side uses the provider's filter.** Filter it with the provider's own `_weather_market_payloads` and its `city_codes`, never a copy. 58 active markets vs 48 weather slugs shows why this matters.
4. **"Same cycle" pinned in the header.** Pair each venue pull with the nearest node cycle and report the time gap. For each difference, report the venue `startDate`/`createdAt` relative to the cycle time.
5. **No side effects.** No network, no writes outside `--out`, and `git diff src/` is empty except for the INFO slice.
