# S4 r1 review — security-reviewer — 2026-10-12
Verdict: SOUND-WITH-CAVEATS — the permit/ledger/firewall architecture is right and nothing weakens a gate, but the AMBIGUOUS-resting rule, the ledger re-registration, the cancel-all scoping and the OS-block test design each have a defect that must be fixed before WP3-WP5 are briefed.

## Findings (ranked)
1. [MAJOR] §6 WP3 step 2 — re-registers open exposure under the venue order id, but `_submit_order` ALREADY registers it pre-POST under `intent.intent_id` with the same booking (exec/client.py:7121-7138). A second `register_open_exposure` with the same booking creates two entries sharing one booking: double counting once the day rolls (`_roll_locked` converts both to uncharged, operator_controls.py:688-709), and the second `settle` raises ("booking is not open"). Required change: keep `intent_id` as the exposure key for the whole life of the resting order (persist intent_id in the venue-id map row so cancel/fill/boot paths can settle it), or specify an atomic re-key. Add RED `test_resting_accept_does_not_double_register_exposure` and a day-roll variant.
2. [MAJOR] §6 WP5 AMBIGUOUS no-id rule — "immediately send a slug-scoped cancel-all, confirm /orders/open empty, then retire" is racy. A POST whose response was lost or timed out client-side may still be processed by the venue AFTER the cancel-all and after the confirming GET. That leaves a GTC order resting with no ledger row and no map row, which is the exact case the plan says it prevents. The IOC argument "created + 65 s" (client.py:1625) bounds an IOC, not a request in flight. Required change: (a) wait out the full request lifetime (maxBlockTime plus transport timeout plus margin) before the cancel-all; (b) re-read /orders/open after a second delay and again require empty before any negative-evidence retire; (c) mandatory GTD on every resting order (see 3) so the residual window is venue-bounded; (d) RED `test_late_landing_post_after_cancel_all_is_caught_by_second_read`.
3. [MAJOR] §6 WP5 "GTD ... if WP0(b) pins it", §8 row 1, §10 Q1 — GTD is optional, so a SIGKILL/OOM/host death (no `on_stop`; the node already "dies with the session") leaves up to ~31 h of unmanaged resting orders whose fills nobody observes. Boot gate and boot sweep only help after a restart that may not come. Required change: make venue-side expiry a hard prerequisite for any live resting order: add STOP S-6 ("no pinned venue-side expiry, or it is not honoured, so no order may rest unattended"), and have `unmappable_resting_order_reason` refuse GTC outright if GTD is pinned. Without GTD, the plan must say who cancels on node death (supervisor job) and name it.
4. [MAJOR] §6 WP4 cancel-all body and boot sweep — `{"slugs":[...]}` is UNVERIFIED (WP0(d)). `post_cancel_all` today is body-less and the venue path is account-wide (write_transport.py:160-175); if the venue ignores the body, every `_cancel_all_orders`, the no-id rule and the boot sweep cancel ALL account orders, including manual and unrelated ones, contradicting "unknown orders are never cancelled silently". Even if honoured, a slug cancel-all kills any unbound order on that slug. Required change: `_cancel_all_orders` and the sweep refuse unless WP0(d)/WP6 positive control has PINNED slug scoping (constant flipped on evidence, like `WRITE_CANONICAL_STRING_VERIFIED`); otherwise fall back to per-order cancel of map-bound ids only. Add RED `test_cancel_all_never_posts_without_slug_body` and `test_slug_cancel_all_refused_while_scoping_unverified`.
5. [MAJOR] §6 WP4 "Security: proving cancel cannot fire" — the proposed `test_post_cancel_order_is_refused_by_the_os_egress_block` cannot pass as written. `post_cancel_all`/`post_order` convert `nautilus_pyo3.HttpError` to `VenueTransportError(... "failed at the transport layer") from None` (write_transport.py:167-170, 186-189), discarding the "Network is unreachable (os error 101)" text that `classify_canary_failure` needs (test_execution_egress_firewall_guard.py:385-405). Anything it does not recognise classifies as REACHED (test at :448). The implementer will be tempted to loosen the classifier (S-4). Required change: the test must wrap the real `HttpClient` in a recording spy that captures the raw pyo3 exception, classify THAT, and assert the VenueTransportError is raised; unsigned dummy headers, a nonexistent order id, a dummy credential; and skip-fail (not skip) when `os_egress_block_attested()` is False. The plan also cites the classifier as "408-448"; those lines are the classifier's tests, the classifier is at ~385-406.
6. [MAJOR] §6 WP4 flow "settle(realized 0) + release_booking" — a registered booking cannot be released publicly (`_refuse_if_registered_locked`, operator_controls.py:614-624), and `settle(realized=0)` true-ups the booking (:882-899), after which `release_booking` raises "already trued up". Required change: one call, `settle(key, booking=b, realized_usd=None, ...)` (releases in full, :896-897), then `restore_live_trading_budget`. RED `test_zero_fill_cancel_settles_exactly_once` asserting `_spent_usd` returns to pre-submit.
7. [MINOR] WP4 restore after boot sweep — `restore_live_trading_budget` is keyed only on the CURRENT permit and clamps to its issued budget (safety.py:857-902). Restoring a slot for an order a previous process (previous permit) spent hands the new permit a slot it never spent. Required change: only restore for venue ids submitted under this process's permit (track a set); a swept prior-process order releases nothing from the permit. State how its seeded spend is handled (conservatively left charged is acceptable; say so).
8. [MINOR] Cancel entry conditions — `_cancel_order` needs a sender seam for cancel, but `_order_sender` is typed around `post_order` (client.py:7182). The plan names no Protocol/injection change, no `factories.py` wiring, and no signing call site (submit signs `sign_headers(_WRITE_METHOD, ORDERS_PATH)` at :7176; cancel must sign `/v1/order/{id}/cancel`). Required change: name the sender interface widening, the wiring file, and a test that the signed path equals the POSTed path (`test_cancel_signature_covers_the_exact_cancel_path`). No new key material is needed; say so explicitly.
9. [MINOR] `post_cancel_order` id validation — "same forbidden-character rule as `order_by_id_path`" is a denylist `/?#\` + whitespace (endpoints.py:125-139); `%2f`, `..` pass. Ids come from venue responses/our map, not users, so low risk, but use an allowlist regex (`[A-Za-z0-9_-]+`) for a write path.
10. [MINOR] Exec import pin — the plan never names x1 (`BANNED_EXEC_TRANSPORT_MODULES`, tests/contract/test_us_source_ingest_egress_guard.py:611-640) or says the pin is unchanged because no new transport module is imported. New tests that import exec modules trip x1 set-equality (focused-gate lesson). Required change: state "x1 unchanged; `test_exec_import_pin_x1_is_superset_of_recorded_baseline` stays green" in WP4, and list it in the focused gate. Also note `exec/__init__.py:20` is a docstring about the wrapper, not the pin.
11. [MINOR] Accountability on partial fills at cancel: a CANCELED order with cumQuantity > 0 (qty is 1, so only a race with a full fill) is routed to the fill path (good); add the converse RED where `cancel` POST returns 200 but the GET shows FILLED and the permit slot is NOT restored.

- `exec/__init__.py:20` (brief) is a docstring line; the x1 pin is in test_us_source_ingest_egress_guard.py:611-640.
- operator_controls.py:504-571, :727-747 and safety.py:857, :953 match. `_cancel_order` 7587, `_modify_order` 7606, `_cancel_all_orders` 7609, `_batch_cancel_orders` 7612 match. `write_transport.py:160` matches.
- `generate_order_pending_cancel` is invoked in WP4 flow but not in the §5 native table: verify it exists on the 1.231 `ExecutionClient` (not checked).

## What the plan gets right
- Cancel never arms the submit intent and never calls the permit assert; it only reduces exposure, is bound to a known venue id, and cannot place an order (the path is `/v1/order/{id}/cancel`, POST-only signer, `PERMITTED_WRITE_METHODS={"POST"}`).
- Every resting submit still goes through the unchanged deny chain: sender, canonical verified, permit, headroom pre-check, `authorize_order_cost`, `assert_live_order_submission_permitted` (single-use, fingerprint-bound; safety.py:953-1046).
- Pins are widened by named rows with non-vacuity proofs and a firewall-delta test; BREEZY_ORDERS_ENABLED, caps, PREREG, `BacktestOrderGuard` and `fees.py` are untouched; unknown open orders keep today's refusal.
- Rejecting `open_check_*`/`inflight_check_*` avoids Nautilus falsely REJECTing live no-id orders.
