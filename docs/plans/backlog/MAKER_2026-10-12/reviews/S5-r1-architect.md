# S5 r1 review — architect — 2026-10-12
Verdict: SOUND-WITH-CAVEATS — the family fits the codebase (one kind, no AUT, advisory gate), but the forecast-day selection, restart semantics, timed cancels, vacuous risk checks and a mis-framed WS STOP must be fixed before PREREG freeze.

## Findings (ranked)
1. [MAJOR] §4 forecast row, WP1 `decide`, WP2 "D and D+1", Q4 — The plan says "no new loader", but the existing state cannot serve D-day rungs. `ForecastQuantileState.value_at` returns the single latest complete vector per station whatever its `climate_day` (strategy/ladder_ev/forecast_state.py:310-325). Each cycle carries exactly one climate_day, the D+1 MAX column (forecast_state.py:191-201; FQ refuses non-D+1 with `NotDPlus1`, forecast_quantile_ladder/decision.py:216-218,277). After the 13Z cycle lands, a D-day ladder would be priced with the D+1 distribution unless guarded. `decide()` receives `p_no_by_rung` + `forecast_cycle_runtime_ns` but not the vector's climate_day, so nothing refuses the mismatch. Age is computed from cycle_runtime, while the repo convention is `now - available_at_ns` (forecast_state.py:112-148). — Required: (a) decide `climate_day == vector.climate_day` or Abstain("forecast_day_mismatch"), plus a RED test `test_vector_for_other_climate_day_abstains`; (b) measure age from `available_at_ns`, the existing convention; answer Q4 that way; (c) before freeze, state the resting coverage per (station, D/D+1, UTC hour) that the 6 h rule actually yields, and reconcile the §8 sample clock and S2's replay windows with it. D-day may contribute ~0, in which case drop D (simplest) rather than build a per-day accessor.
2. [MAJOR] WP2 strategy `resting` map, WP3 join — Restart semantics are undefined. The would-be resting map is in-memory. The node restarts daily and up to 3×/5 min mid-day, and a real GTC rest survives a node restart at the venue. The JSONL has no boot/shutdown marker, so the scorer either (a) treats pre-restart rests as alive through downtime, crediting fills the node never saw, or (b) silently re-rests with a new t0. Neither is tied to S4's real restart behaviour. — Required: S5 adopts S4's restart contract (cancel-on-stop, or persist-and-reconcile) explicitly. WP2 writes a `SHADOW_BOOT`/`SHADOW_STOP` line. WP3 gets RED test `test_rest_spanning_node_downtime_follows_s4_restart_contract`.
3. [MAJOR] WP2/§3 hard cancels — The hard cancels have no timer. `decide` runs only "on each book, forecast or obs event". The 09:00 LST cancel and the 6 h forecast-age expiry are time-triggered. On a quiet book (empty NO bid side is common) the cancel lands late. The scorer then credits fills in exactly the post-09:00 repricing window that §6.9 tests for adverse selection. — Required: native `self.clock.set_time_alert` per station for the cancel hour and per forecast expiry (Nautilus-native, no new machinery). The scorer independently clamps every rest's end to min(cancel deadline, available_at+6h). RED test `test_cancel_fires_at_0900_lst_with_no_market_event`.
4. [MAJOR] WP0 item 4, R-4, gate 5 — The risk checks are vacuous in shadow. `RiskManager.evaluate_order` (weather_common/risk.py:572-646) nets against `PortfolioSnapshot`. Shadow positions never reach the Nautilus cache, so `exclusive_conflict` (:517-530), `max_position` and simultaneous-position checks always pass, and gate 5 "§4 limits respected" becomes a tautology. Separately, spec §4 enables `exclusive_bucket_conflict` and also stacks 2 NO rungs per ladder. Whether `mutually_exclusive_group` groups sibling NO legs is unverified; if it does, live would refuse the 2nd rung that shadow counted. — Required: simplest path, no `evaluate_order` in shadow. Enforce the structural limits (qty 1, ≤2 rungs, ≤8 simultaneous, allow_short False) as pure checks inside `decide` and count them via `RefusalCounter`. Before freeze, WP0 verifies `exclusive_conflict` on two NO legs of one ladder and records it, because PREREG pins `MAX_RUNGS_PER_STATION_DAY=2`.
5. [MAJOR] §2 S-2, WP0 item 3 — The WS-cap STOP rests on a wrong model.
   - Subscriptions are per base slug, and the NO leg shares its YES slug (adapters/polymarket_us/symbology.py:277-325).
   - The data client refuses a NO-leg feed subscribe (data.py:1632-1656); the NO book arrives through the YES slug, which is the FQ precedent (forecast_quantile_ladder/strategy.py:356-361).
   - The pool already shards ceil(N/10) connections (websocket.py:1217-1262; factories.py:694-704), so "native multiplexing" exists.
   - The node's data client also subscribes every discovered listed slug through `_reconcile_discovered_subscriptions` (data.py:1453-1497) whatever the strategy requests, so the maker adds ~0 net subscriptions.
   - The "× 2 legs" arithmetic is wrong: at most 48 slugs over 5 shards.
   - The residual risk is the never-probed connections-per-key cap (websocket.py:1245-1250). That is status quo today, not a maker-specific STOP.
   — Required: replace S-2 with a WP6 health check (boot `subscribed_slug_count`, zero `silent_subscriptions` for maker slugs). WP2 reuses FQ's YES-subscribes / NO-registers-handler shape and gets RED test `test_no_leg_book_received_via_yes_slug_subscription`.
6. [MAJOR] §2 E3 — Simplest path: S4 is not needed to start the shadow run. The shadow never submits. Gating a 230–320-day calendar clock on the IOC→GTC exec rebuild (byte-pinned client, egress pins) delays the clock for no shadow payoff; `OrderFactory.limit` construction needs no S4. — Required: drop E3 from entry and move "S4 merged + gate-green" into G8 (activation readiness), read at promotion. Exception: keep only the part of S4 that fixes restart semantics (finding 2) if S4 is the authority for it.
