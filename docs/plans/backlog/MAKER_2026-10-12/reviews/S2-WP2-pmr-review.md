## Findings
H-1 Abstention counted per call, not per station-day. `load_p_no` :310,:314 increments a Counter on every decision instant. Delta (e) (r4_delta L129-132) makes bid-bearing = >=1 attempt, so forecast-abstained covered days are legitimately NOT bid-bearing (spec §3 L81-86: stale/missing -> cancel, no bid; an abstention is not an attempt, and counting a stale forecast as an attempt-refused day would be unfaithful to the rule and to `test_bid_bearing_counts_guard_refused_attempts`). But the days dropped this way must be reported per station-day, else the denominator shift is invisible and n_sd (covered bid-bearing) silently shrinks, which delays the sample clock and, if forecast-less days correlate with fills, biases the rate. Fix: key abstentions by (station, day, reason) set; expose `abstained_days()`; WP6 reports covered-but-never-forecast-visible count (extends (i)6).
H-2 Docstring/claim error, p_hat vs bounds. Live `decision.evaluate` trades NO on `ev_net_no(p_upper)` (decision.py:~351), YES on p_lower; p_hat is only forwarded for logging. Module docstring :9-12 and `PNoAtInstant` say "what decision.evaluate trades on". The maker spec trades on the POINT (p_hat) by design, so the code is right and the sentence is wrong. Fix text: "the spec §3 point estimate (= live p_hat; the live taker rule uses the bound)". Also record p_no_lower = 1 - p_upper in `bounds` consumers, not p_yes bounds mislabelled as NO.
M-1 No release-instant API. Spec §3 re-evaluates "on each forecast release"; a new vector that drops p_no below P_MIN must cancel the resting bid at available_at. Loader only answers point queries, so a simulator evaluating on book events alone leaves a stale bid resting (optimistic fill). Fix: `release_instants(station, day, stress) -> tuple[int,...]` (sorted stressed available_at of complete vectors) and a WP4 test that a mid-window release cancels.
M-2 `load_p_no` accepts any `decision_ts_ns` (:293). Callers feeding the fill ts or a later book ts get a vector the bot could not have had at the decision. Fix: document contract "decision_ts = the event instant at which the bid was posted/repriced, never the fill"; WP4 test asserting p_no ts <= post ts for every scored fill.
M-3 NaN/non-finite p. `ladder_p_yes` returns whatever the EMOS cdf yields; no finite/[0,1] check (WP3 review already flagged NaN p_yes). A NaN passes `p_no < P_MIN` False. Fix: validate in `ladder_p_yes`, count `nonfinite_p`, return None.
M-4 `except ValueError` in `ladder_p_yes` :212 also swallows the 1e-12 sum-check and empty-draws errors and re-routes to complement ladders. Narrow it to the partition errors (`_assert_complete_partition` messages) or pre-test partition-ness explicitly.
L-1 Stress/stale interplay: poll_lag/plus60 shift `available_at` that the 8 h stale test also uses (:290); stress makes vectors look 15/60 min fresher at the stale edge (anti-conservative at the boundary). Compute age from the unstressed available_at, or accept and state.
L-2 `read_partition` loads the whole (date,hour) file including KNYC rows (:170) before the station filter; licence says never NYC. Pass a pyarrow station filter, or note in the licence that partitions are read whole and NYC is discarded unused.
L-3 `from_root` does not refuse day == 2026-10-01, > 2026-10-13, or days outside the frozen set (driver is the only gate). Cheap defence in depth.
L-4 VERIFY_FIRST_DAY hard-coded; amendment §3 allows an addendum-named substitute day (<=2026-06-30). Parameterise via the driver's checked addendum.
L-5 `_first_max_column` relies on dict last-wins over a descending sort to keep the earliest column (:132); correct but obscure and no duplicate-row (re-fetch) guard. Use min() per variable and assert one row per variable.
