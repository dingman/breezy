## Findings (ranked)
1. [MAJOR] §1.6/§1.8, WP5 `verdict()`, Q4 — GO can be emitted with §6.9 INCONCLUSIVE. `verdict(fill_rate_base, s69)` has no stated mapping for INCONCLUSIVE. With ~4-7 expected YES settlements, ~23 date clusters and fewer than a few filled losses, bootstrap draws with zero filled losses give T1 < 0, so FAIL is practically unreachable. T2 is undefined in draws with zero filled or zero unfilled bids. So GO would mean only "fill rate >= 0.10". Required: (a) a fourth outcome, `GO-UNSCREENED` (or `INCONCLUSIVE`), emitted whenever §6.9 is underpowered, and never printed as bare `GO`; (b) declare the zero-denominator draw rule for T1/T2 (drop and count, report the count); (c) print minimum detectable filled-loss rate and expected YES count beside the verdict; (d) add an exact one-sided binomial/Fisher p next to the bootstrap p, because ~23 clusters and ~0-3 events make the bootstrap degenerate. Answer to Q4: INCONCLUSIVE != FAIL is right, but it must not unlock GO. Q3: NO-GO on the base (optimistic) rate; if base >= 0.10 and the 2x stress < 0.10, print `GO-FRAGILE`.

4. [MAJOR] §1.2, WP0.2, WP4 — tape-integrity contract is missing. "Print stream not covering the bid window" has no measurable definition. The catalog carries `custom_quote_tape_gap` records (`QuoteTapeGap.covers`, `tape_records.py:162`) and `custom_depth_truncation` (`DepthTruncation`, `tape_records.py:450`), and the plan uses neither. Required: exclude or cancel exposure inside any gap overlapping `[t0, cancel)`, and report excluded exposure-hours. Flag episodes whose Q0 frame has a `DepthTruncation` row at the same `ts_event` (Q0 is then a lower bound) and report them separately. Derive the replay start day from measured print coverage, not the asserted "09-19": 09-18 has only 4,223 prints, and climate day 09-19's bid window opens 09-18 12Z.
5. [MAJOR] WP4 `Event`, WP2/WP3 — event-order and clock contract is unspecified. `Event` has no schema and equal-`ts_event` ties have no total order (depth vs print vs forecast release vs cancel). The ordering affects `depth_ts_used <= t0` and `t0 < ts`, and so the leak direction. Required: a total order `(ts_ns, kind_priority, seq)` with a RED test. Name the clock: book and print `ts_event` are the venue clock; forecast `available_at_ns` and observations are host or true UTC. `VenueClockOffset` (`tape_records.py:227-244`) records a ~131 s host-venue offset and the plan does not read it. 6. [MAJOR] §4 Nautilus row, WP4 rule — the conclusion (no BacktestEngine for Stage 0) is right, but the argument is weak where it matters. (a) Reason (a) is moot: the census has zero `NO_AGGRESSOR` prints, so the `engine.pyx:4689-4692` both-sides behaviour never triggers here. The cite is accurate (that branch sets bid and ask raw to the trade price) but it is a hypothetical, not evidence. (b) "Deleted level credits a fill, more optimistic than §6.1" is asserted, not measured. §6.1 as coded sums every BUYER print at YES price >= a at full size, so a sweep through `a` counts toward Q0 although it consumed nothing at level `a`. 7. [MAJOR] WP5 `ScoredBid`, §6.9 — the unit of analysis under cancel-replace is undefined. A (station-day, rung) chain has several episodes, each with its own `p_no_at_t0` and bid. `ScoredBid` carries one `p_yes`/`stratum`. Filled strata come from the filling episode, but unfilled strata have no rule, so T2 compares unlike strata. Episodes in one chain are also correlated. Required: pre-declare one row per chain with a stratum rule applied identically to filled and unfilled (e.g. p_no at first placement, plus time-weighted as sensitivity). The spec requires the station-day unit beside the position unit (spec §3, "gates use the stricter"), and WP5 reports only one: add it.
