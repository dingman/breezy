# S2 r1 review — prediction-market-reviewer — 2026-10-12
Verdict: UNSOUND — the WP4 fill rule mis-counts queue volume in exactly the regime the rule creates (bid far below the market), so the fill rate it feeds the <0.10 NO-GO gate is biased low; the §6.9 test is also too underpowered to support a "GO" and the verdict mapping is forkable.

## Findings (ranked)

1. [BLOCKER] §5 WP4 "Rule": `V >= m*(Q0+1)`, Q0 = sum YES ask size at price <= a, V = BUYER prints at YES price >= a — Q0 and V are measured over different price sets, so V cannot reach Q0 whenever depth sits at better prices. Under §3, bid = min(0.80, best_no_bid+0.01) and best_no_bid = 1 - best YES ask. For a tail rung with YES ask ~0.05-0.15, best NO bid is ~0.85-0.95, so the bid is capped at b=0.80, i.e. a virtual YES ask at a=0.20, ABOVE every displayed ask. Q0 then counts all ask size at 0.05..0.20 (price priority puts it ahead of us). A buyer sweeping up to >=0.20 consumes that size in prints at prices BELOW a, which V excludes. Only the sliver printed at >= a counts. Result: V << Q0 even when the book was swept through our level, so those fills are never credited. Fill rate is biased down, and the 0.10 gate (S-1) can kill the family on a simulator artefact. In the other common case (b = best+0.01, Q0 = 0) the rule is near-vacuous: V>=1 or V>=2 on any buyer print, so the "2x stress" does nothing. Same code, opposite biases, depending on regime.
   Required change: use the standard trade-through/queue rule. FILL at the first BUYER print with YES price strictly > a (the sweep necessarily passed us); at price == a, credit only when cumulative BUYER volume at exactly a since t0 >= m*(size ahead at exactly a + 1) (better-price levels are cleared by definition if the print is at a). Keep m*(Q+1) for the same-level case only. Add RED tests: `test_sweep_through_our_level_fills_even_when_better_levels_were_deep`, `test_print_at_better_price_never_fills`, `test_same_level_needs_queue_ahead_then_us`. Report the fraction of fills that are trade-through vs same-level; trade-through fills are mechanically adverse (the YES price moved 0.10 against the tail) and must be shown separately.

2. [BLOCKER] §5 WP5 / §1.8 / open Q4 — verdict is forkable and INCONCLUSIVE has no mapping. `verdict()` returns GO/NO-GO/NOT_COMPUTABLE, but WP5 says <2 filled losses is INCONCLUSIVE ("neither PASS nor FAIL"). What does `verdict` return for INCONCLUSIVE, and for 2..6 losses with p>0.05? Nothing in the plan states it, so the executor chooses after seeing the numbers. Power (scoring_core.py:216 bootstrap, 2000 draws, seed fixed): with n~30-60 fills at mean p_yes ~0.04, T1 threshold is loss rate 0.06. A FAIL (p<0.05) needs roughly >=8-10 losses in distinct date clusters, i.e. a true loss rate several times the model. A true 2-3x adverse-selection (still far below the economic breakeven loss rate ~0.19 at b=0.80) is detected with probability well under 50%. So "no FAIL" carries almost no information, yet the verdict string is GO.
   Required change: (a) freeze, in the plan text before any run, a verdict table: NO-GO if base fill<0.10, or stressed fill<0.10 [see 3], or §6.9 FAIL, or net-expectancy cluster-CI upper bound <0; NOT_COMPUTABLE if fills<20 or fill-clusters<10 or filled-losses<2; otherwise the label is `NOT-KILLED` (proceed to S4/S5 shadow), never `GO`. (b) Print a pre-run power line computed from the realised fills and mean p: P(FAIL | true loss = 1.5x, 2x, 3x model p), by parametric bootstrap. (c) Add an exact one-sided Poisson-binomial/binomial tail for L_filled vs sum(p_yes) as a sidecar (the cluster bootstrap degenerates at 0-3 events).

3. [MAJOR] §9 Q3 / S-1 — NO-GO keyed on base fill rate only. Base is optimistic by construction (spec §6.1 says so), so base<0.10 is a safe kill, but a permissive "GO" off base>=0.10 is the dangerous error. Required change: kill on base<0.10; allow `NOT-KILLED` only if the 2x-stressed rate is also >=0.10. Also print implied days-to-200-positions (spec §9.15 assumes fill rate 0.3, ~100 days; at 0.10 it is ~300 days) so the reader sees the 0.10 floor is not a viability number.

4. [MAJOR] §5 WP5 `ScoredBid` — the p used for T1/T2/strata is unspecified. Stratum and `p_yes` must be the model p_YES at the FILL instant (the information the maker had), not at first t0 and not the upper band; for unfilled bids use the last live p before cancel. The bid is cancelled when p_no < 0.94 so t0-p and fill-p differ. Also state point vs `upper` (rung_probability_interval returns (mean, lo, hi), quantile_density.py:393-443). Use point for T1 (spec says "model mean p_YES"). Fill/unfill is per (station-day, rung) pair, not per episode; define it, and collapse cancel-replace episodes to one record, otherwise unfilled bids are over-counted and T2 is diluted.

5. [MAJOR] §5 WP5 T2 — pooled `L_filled - L_unfilled` is confounded by stratum mix (filled bids skew to higher p_yes strata because bids at lower b fill less). Use a stratum-standardised difference (weights = filled counts per stratum) for the pooled T2; keep per-stratum descriptive. Also T2 is dominated by the mechanism in finding 1 (fills happen when YES reprices up); say so in the report so a T2 FAIL is not read as a model failure.

6. [MAJOR] §6 "UNVERIFIED" calibration / open Q5 — tail calibration. Two problems. (i) The artefact (`nbp_calibration_pm_us_crh_fq_v1_2026-09-30.json`, created 09-30 02:55, n_min 592) records no fit/train end date in its keys (checked: cdf_method, delta, emos_*, n_min, sigma_d, ... only), and the replay window 09-19..10-11 overlaps the period it was built in. The plan must pin the artefact's training/validation cutoff (from the build manifest) and mark replay days <= cutoff as in-sample, or exclude them. Otherwise p_NO is a leak-adjacent in-sample probability. (ii) Selecting "lowest p_YES passing 0.94" is selection on model noise (winner's curse); reliability measured only on ~184 selected bids with <=6 expected losses cannot validate p=0.97. Cheap fix with real power: report observed YES frequency for ALL (station-day, rung) pairs with model p_YES<0.06, regardless of bid/fill (~4 rungs x 92 station-days), by lead bucket, next to the selected set. Answer to Q5: no refit; use the artefact, but require the in-sample cutoff and this all-rungs table before any NOT-KILLED label.

7. Required change: WP2 verify-first STOP must also print, per station, the vintage age distribution at 00:00/06:00/09:00 LST on D; WP6 report must include "bid-live hours per station-day" and the fraction of station-days with zero live bid-hours. A fill rate over a window where bids are cancelled by staleness is a rate of the cancel rule, not of the maker.

8. [MAJOR] §5 WP4 depth truncation/staleness. Depth10 shows 10 levels; with a 1c tick and a=0.20, the 10th displayed YES ask may be below a, so Q0 (sum price<=a) is a lower bound with unknown censoring. Under the corrected rule (finding 1) this matters only for same-level queue, but a must also be asserted inside displayed range or the episode flagged `q_censored`. Also: t0 uses "last frame at or before t0": add a max-frame-age guard (stale snapshot is a quote older than the cycle) and a marketability guard: assert a > best YES bid (i.e. b < NO ask = 1 - best YES bid, resting_bid_core.py leg_ask_price) or the "maker" bid is a taker; count and drop such t0s.
