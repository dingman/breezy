# S3 r1 review — prediction-market-reviewer — 2026-10-12
Verdict: SOUND-WITH-CAVEATS — the path model (win 1-BE / loss -BE, exclusive rungs, FQ bar unchanged) is correct, but the dependence calibration is weaker than the plan states, the fill-rate input is optimistic and mis-bounded, and the stop being certified is not the stop the spec names. Two MAJORs must be fixed before the binding run is trusted as a terminal KILL.

## Findings (ranked)
1. [MAJOR] §4.1 "Climate-date clustering" and §8 risk row 6 — the plan says ρ 0.25 and ρ 0.5 "bind c". They do not. `_BINDING = {(H0,none),(S4,none),(S5,bind)}`; S5-"half" (ρ=0.5) is report-only (`fq_loss_floor_mc_report.py:80`, role switch `:128`, solve loop `:175`; outer mirror `fq_loss_floor_mc_outer.py:45`). With `rho_hat=None`, ρ_bind is the 0.25 floor (`fq_loss_floor_mc_rows.py:286-289`). FQ's ρ̂ came from pool data; the maker has none, so c is calibrated at the weakest dependence the engine allows. Failure: c is too small, null false-stop is above nominal, G3 power is flattered, REACHABLE is declared on an optimistic c. Change: add a `binding_rows` parameter (default = current set) and make S5-half binding for the maker run, or justify ρ=0.25 with data. Pin it in code before the run.
2. [MAJOR] §4.1 vs TE-2 evidence — the dependence structure tested is the wrong shape. TE-2 clusters are station-events (consecutive climate days at ONE station): 14 station-days in 7 clusters, LAX a single near-certain cluster, TAIL = 43.7% of loss (`docs/evidence/te2/phase_b/fq_v1_loss_taxonomy_2026-10-12.md`; TE-2_plan_r3_2.md:28,64). The engine resamples dates i.i.d. (`sim.py simulate_family`) and its only dependence knob is a one-factor Gaussian copula ACROSS stations within a date (`sim.py:36-47`). It has no serial same-station persistence, and a Gaussian copula has zero tail dependence. Persistent forecast bias is exactly what a loss stop must survive, and under H0 it fattens the loss distribution, so the i.i.d. c is again too small. Q3's ρ=0.9 row does not address this; it is still cross-station-same-date. Required: a station-persistence calibration row (block-resample station-days in runs of L consecutive days, L pinned, e.g. 3 and 5), binding or at least a veto-capable report row, and an explicit statement that REACHABLE is conditional on it. Answers Q3: ρ=0.5 binding (finding 1) plus a persistence row; ρ=0.9 report-only.
3. [MAJOR] §1/§6 WP4/§2 — fill-rate input. (a) Spec §6.1 says the base fill rule is optimistic and the 2x stress is mandatory; the plan takes `f_lo` from the Stage 0 CI with no statement of which rule. Reachability at an optimistic f is the wrong side to be optimistic on. Require f_lo from the 2x-stress rule (or the min of both). (b) Stage 0 covers about 08-30..09-25 (~27 climate dates); a cluster-bootstrap lower bound on that has poor coverage, and "STOP 1: fill rate below 0.1" (§2) does not say point or bound. Define both: STOP 1 on the point estimate only; a point-REACHABLE/f_lo-UNREACHABLE result must route to "UNDERDETERMINED, carry to S5 shadow" rather than terminal KILL, because Stage 0 is exploratory by invariant and the hard KILL uses a statistic it calls non-evidence. (c) Template fills are i.i.d. Bernoulli per rung (§4.1); real fills are date-clustered and over-dispersed, while T_low is the expected count (`gate.py:136-142`, floor of n·λ·p). Add a design-effect-deflated cell (spec §6.4 uses 1.5) at λ/1.5, or take T_low from a stated lower quantile.
4. [MAJOR] §4.2 / spec §4 — which stop is certified? Spec §4 says the family's loss stop is "LD-OBF on the Wilson bound, look every 10 completed positions" (positions as unit). S3 certifies the A1 sqrt-boundary clock over station-day ticks (`select_alpha`, `gate.py:266-333`). Plan §4.4 then calls the A1 floor α "carried over unchanged from FQ" while spending the LD-OBF looks from α_maker. Two stops, two units, one gate (spec §7.8 names only A1). Failure: A1 passes, S5 ships a different stop whose reach at ~2 positions/day (10 positions = 5 days, ~20 looks) was never tested. Required: state in the plan which stop S5 will freeze; if A1-sqrt only, spec v0.3 must drop LD-OBF-as-loss-stop; if both, S3 needs a reach check for the LD-OBF stop at f_lo.
5. [MAJOR] §4.1 "At most 2 legs…" — G1 reach is evaluated on an impossible path for 2-leg days. `_median_z` -> `all_lose_z` sets h=0 for EVERY leg (`rows.py:326-334`; `report.py:88-95`). Two NO legs on distinct rungs of one ladder cannot both lose, which the plan itself asserts. Analytically (b=0.75, BE=0.763): infeasible z about -3.06, worst feasible two-leg day (one leg hit) z about -1.05, single-leg day -1.80. G1 uses the median over a mix of 1- and 2-leg days, so z is overstated 1.7-3x on 2-leg days. G1 will probably still pass at ~100+ ticks (G3 is binding), so this is unlikely to flip the verdict, but the statistic is wrong by the plan's own model. Not verified numerically (no runs permitted). Required: add a test `test_g1_all_lose_path_is_feasible_for_exclusive_legs` and report z for the feasible-worst path alongside; G1 must pass under the feasible one.
