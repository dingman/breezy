# ING-2 S3: bounded ingest memory via a coalesced streaming read (plan r2, 2026-09-26; UNDER PEER REVIEW)

**Supersedes** r1 (`ING-2_S3_plan_r1_2026-09-26.md`). **Evidence:** `ING-2_S3_stage0_findings_2026-09-26.md`.

**Measured facts this plan relies on:**
- F3 dominates. The 698 MB `instrument_status` file (c0c77dec) holds 891,170 IPC messages of one row each.
- Native `read_all()` peaks at about 5.87 GB. Post-import RSS was 294 MB and after-read RSS was 5,019 MB, so the read costs about **5.3 KB per message**.
- `table.nbytes` is 98 MB, about **110 B per row**. The message overhead is therefore about **48× the logical size**.
- Materializing the table to objects adds about 280 MB, roughly **2.9× nbytes**.
- F4 plateaus at 1.3–1.5 GB and is bounded.

**Sequencing (A10).** The work ships in two slices:
- **S3a** is the coalesced read plus the fast path and per-file path, the Phase 0 arms, the EXTEND read swap (without chunking), the salvage coalescing, and the A8 write-mismatch detector.
- **S3b** is EXTEND chunking. It is **conditional**: it is built only if the trigger in §Phase 0 fires. Each slice can be merged on its own.

## Acceptance criteria

### S3a

- **AC-S3-1 (peak memory, ΔRSS).**
  - **Fixture:** one QuoteTick feather written by the real `StreamingFeatherWriter`, one row per message.
  - **Measurement:** each measurement runs in a fresh child process (P2). ΔRSS = `ru_maxrss` at the end minus `ru_maxrss` at the baseline. The baseline is taken after imports **and** after a 10-row warm-up run of the same path, which absorbs lazy pyarrow, parquet and compute initialization.
  - **Ratio:** at N = 100K, each path's treatment ΔRSS must be ≤ 25% of the control ΔRSS for the same path. The paths are fast (mirror), per-file, and EXTEND (S3a, unchunked). The control is the identical script with only the `quote_tape_ingest_cli.read_feather_coalesced` seam replaced by `lambda fs, path, **kw: catalog._read_feather_file(path)`. Expected control ≈ 0.53 GB at 5.3 KB/message.
  - **Scaling:** from N = 100K to 200K (treatment only), ΔRSS growth must be ≤ k × Δ`table.nbytes` + 32 MiB.
    - k = 2 for the fast and per-file paths.
    - k = 8 for S3a's unchunked EXTEND, because object materialization is about 2.9× nbytes and `write_data` builds one more table.
    - The control scales at about 48×, so either bound separates message-count scaling from logical-size scaling.
- **AC-S3-3 (layout unchanged).**
  - The mirror produces the same relative parquet filenames and the same rows as native `convert_stream_to_data` on twin catalogs, in both per-instrument and flat layouts (T-R4). Full row sequence equality is the P3 assumption check.
  - The per-file path produces the same files as before.
  - The existing EXTEND tests, `TestTheMixedCatalogLayoutIsPinned`, and `test_convert_live_capture_definitions` stay green.
- **AC-S3-4 (invalid streams).**
  - A stream that goes invalid mid-read returns `None`, never a partial prefix. A missing path returns `None`. Both match native (`parquet.py:2792-2800`).
  - The per-file path still turns `None` into `failed` (cli:1296-1306). The fast-path mirror keeps native's silent `continue` (`:2645-2646`).
- **AC-S3-5 (production check, after merge).**
  - **Setup:** run the merged code through `run([...])` on a scratch copy of c0c77dec, under `MemoryMax=2G -p MemorySwapMax=0`.
  - **(a) Fast path:** ΔRSS ≤ 1 GiB.
  - **(b) Forced EXTEND:** first seed a partial slice by converting a message-boundary **prefix** copy (about 10% of the messages) under the same cap, then run the full file. ΔRSS ≤ 1 GiB. If (b) fails, that is S3b trigger T-b.
- **AC-S3-6 (write integrity).** An EXTEND write whose rows do not all land raises `ExtendWriteMismatch`. The file stays unmarked and the type or file is counted `failed` (T-R8).
- **AC1 (F4) stays demoted.** The plateau is bounded and pool `bytes_allocated` = 0.

### S3b (only if triggered)

- **AC-S3-2 (chunk size).**
  - No call to `_handle_table_nautilus` or `write_fresh_capture_rows` in EXTEND receives more than `EXTEND_CHUNK_ROWS + R − 1` rows. R is the longest run of equal `ts_init` in the sorted table.
  - The dedupe window of each chunk is that chunk's own [lo, hi].
  - Chunked output equals unchunked output as a row set, including a tie that straddles a chunk boundary and the Bar `-INTERNAL` case.
- **AC-S3b-1.** The EXTEND scaling bound tightens to k = 2, and Phase 0 arm 3b passes the 1 GiB line.

## Trade-offs

- **Writer-side batching: rejected.** `StreamingFeatherWriter.write` serializes each object separately (`serialize_batch([obj])` + `write_table`, `writer.py:259,265`). `flush_interval_ms` only controls when to flush, and `StreamingConfig` has no batch field.
- **Subclassing the catalog to override `_read_feather_file`: rejected.** It changes native behaviour silently and hides the base-class monkeypatch tests.
- **One parquet per chunk on the native path: rejected.** It would be refused as non-disjoint (closed intervals, `:2689`), and it would change the file layout.
- **`pa.concat_tables` for assembly: rejected (P1).** It raises when there are zero tables, and the schema metadata would come from the first table rather than the reader.
- **Pinning local-fs only: rejected (A3).** Reading through `catalog.fs` matches native, costs nothing, and does not diverge silently on another fs.
- **Chunked EXTEND up front: deferred to S3b (A10).**
  - Stage-0 shows materialization adds about 280 MB over the read. S3a may well bring unchunked EXTEND under the line.
  - Chunking adds the tie rule, more files, and ordering assumptions. It is built only against measured need.
- **CHOSEN.** Coalesce batches while reading. Keep one native `_convert_feather_table_to_parquet` per feather file, driven by a Breezy mirror of the native loop.
- **Residual.** Memory still scales with the **logical** size of the largest single file (about 98 MB today, and about 3× that on unchunked EXTEND). Option D (a streaming parquet writer) is held in reserve and is the last rung of the Phase 0 ladder.

## Architecture

### S3a

**1. NEW `breezy.persistence.feather_read` (pyarrow only; never imports `breezy.runtime`, per lint-imports).**
- `COALESCE_ROWS = 8192`. At the measured 5.3 KB per message, the pending group is at most about 43 MB transient. At ladder rung L1 (1024) it is about 5.4 MB.
- `BatchCoalescer(schema, coalesce_rows)`:
  - `add(batch)` appends the batch to a pending list. When the pending row count reaches `coalesce_rows`, it flushes.
  - Flush is `pa.Table.from_batches(pending, schema=schema).combine_chunks().to_batches()`. The result is extended onto `self._done`, and the pending list is dropped.
  - `to_table()` does a final flush, then returns `pa.Table.from_batches(self._done, schema=schema)`. With zero batches this gives an empty table carrying the schema, the same as `read_all`.
- `read_feather_coalesced(fs, path, *, coalesce_rows=COALESCE_ROWS) -> pa.Table | None`:
  - Returns `None` if `not fs.exists(path)`.
  - Otherwise, inside `try`: `with fs.open(path) as f`, then `reader = pa.ipc.open_stream(f)`, then loop on `reader.read_next_batch()` into a `BatchCoalescer(reader.schema, …)` until `StopIteration`.
  - `except (pa.ArrowInvalid, OSError): return None`. This covers the open, the schema read and every batch, the same scope as native.
  - The schema metadata survives through `schema=reader.schema`, which `_identifier_from_table_or_path` needs.
  - `KeyboardInterrupt` and other exceptions propagate.

**2. Fast path: `_convert_stream_natively(catalog, instance_id, data_cls, subdirectory, *, target=None) -> None` in `quote_tape_ingest_cli`.** This is a mirror of `parquet.py:2636-2654`:
- `used_catalog = catalog if target is None else target` (A1).
- For each `feather_file` in `catalog._list_feather_data_files(kind=subdirectory, instance_id=instance_id, data_cls=data_cls)`:
  - `feather_table = read_feather_coalesced(catalog.fs, feather_file.path)`.
  - If it is `None`, `continue` (native parity).
  - Call `catalog._convert_feather_table_to_parquet(feather_table=…, feather_path=feather_file.path, data_cls=data_cls, used_catalog=used_catalog)`, using native defaults (`use_ts_event_for_ts_init=False`, `identifiers=None`).
  - Then `del feather_table`, so no more than one file's table is alive while the next file is read.
- `default_convert` (:729-738) calls `_convert_stream_natively` in place of `catalog.convert_stream_to_data`. A non-disjoint `ValueError` still goes to `_extend_overlapping_stream`.

**3. Per-file path (:1295).** Becomes `table = read_feather_coalesced(catalog.fs, str(path))`. Everything else is unchanged, including the transform at :1307 (`convert_bar_type_to_external=True`) and the fallback at :1343-1344. The fallback now wraps `ExtendWriteMismatch` as `failed`, leaving the file unmarked (§7).

**Seam.** `quote_tape_ingest_cli` does `from breezy.persistence.feather_read import read_feather_coalesced`. Every call site resolves through that module global, so there is one monkeypatch seam: `quote_tape_ingest_cli.read_feather_coalesced`.

**5a. `_extend_overlapping_stream` (:784).** The read is swapped to `read_feather_coalesced(catalog.fs, feather_file.path)`. EXTEND is otherwise unchanged in S3a: it materializes the whole file and runs one `write_fresh_capture_rows` per file.

**6. Salvage `_scan_stream(collect=True)` (`feather_preflight.py:346-355`).** `batches.append(batch)` becomes `coalescer.add(batch)`, and the table becomes `coalescer.to_table()`. The prefix semantics (stop at the first incomplete message) and the `pa.OSFile` + `tell()` accounting are unchanged. `collect=False` is untouched.

**7. Write-mismatch detector (A8) in `quote_tape_salvage.write_fresh_capture_rows`.**
- Let `root = write_target._make_path(data_cls=data_cls)`, the type root with no identifier (`parquet.py:2465-2479`). `before` is the set of `*.parquet` under `root` from `write_target.fs.find(root)`, or empty if `root` is absent.
- Call `write_data(fresh, skip_disjoint_check=True)`, then compute `after` the same way.
- `written` = sum of `pq.read_metadata(f, filesystem=write_target.fs).num_rows` for `f` in `after − before`.
- If `written != len(fresh)`, raise `ExtendWriteMismatch(ValueError)`. Its message never contains "non-disjoint", so it is never misrouted into EXTEND. It names the count and the type, never an instrument id or a value.
- Why it fires: `_write_chunk` skips an existing filename with a bare `print` (`parquet.py:378-380`). The dedupe on (instrument_id, ts_init) makes a collision practically impossible, so this is a tripwire that turns a silent loss into a loud `failed`.
- `default_convert` already maps a `ValueError` from EXTEND to `failed` (cli:1202-1207). The per-file fallback catches `ExtendWriteMismatch` explicitly, logs it at ERROR and counts it `failed`, without calling `_mark_file_converted`.
- Cost: one `find` of one type root before and after each EXTEND write, plus footer-only reads of the new files.

### S3b (conditional; see the trigger)

**4. `_extend_table_chunked(catalog, write_target, data_cls, table) -> tuple[int, bool]`.** It returns `(written, streamed_any)`.
- It calls `_apply_stream_conversion_transforms(table, use_ts_event_for_ts_init=False, convert_bar_type_to_external=False)` **once** (A4), which sorts by `ts_init` only if the table is unsorted.
- It slices the result into `EXTEND_CHUNK_ROWS = 50_000` rows. Each cut advances past any run of equal `ts_init`.
- For each chunk it calls `list(_handle_table_nautilus(chunk, data_cls))` with defaults (a sorted slice skips the sort, so this is an O(n) check), then `write_fresh_capture_rows`.
- **Bound:** chunk rows ≤ `EXTEND_CHUNK_ROWS + R − 1`, where R is the longest run of equal `ts_init`.
  - Degenerate case: R ≥ the file's row count gives a single chunk, which is exactly today's unchunked EXTEND. That is no regression, but no gain either.
  - Phase 0 arm 3b records R on c0c77dec.
- **Why ties stay together:** unchunked EXTEND writes both rows of an in-file same-key pair. A split pair would have its second row dropped by the next chunk's dedupe query, so the tie rule is what makes chunked equal unchunked.
- **Ordering:** both paths apply one deterministic sort to the identical full table, so stability is not needed for chunked ≡ unchunked (P3).

**5b.** `_extend_overlapping_stream` and the per-file fallback at :1343-1344 call `_extend_table_chunked`.

## Risks

- **R1.** The mechanism is not isolated (decode buffers vs table chunks vs glibc arenas). Mitigation: Phase 0 arm 0 separates iteration cost from retention, and the ladder has L2.
- **R2.** Ordering. The P3 assumption is that `pc.sort_indices` is stable on ties. T-R4(d) checks it for S3a, and T8a and T-R5 check it for S3b. The recorder normally writes files already sorted, and `_enforce_monotonic_ts` then skips the sort (`:2754-2763`), so order is preserved exactly.
- **R3 (S3b).** Duplicates at chunk boundaries. The tie-extension rule prevents them, and T8a pins it. The degenerate bound is stated in Arch §4.
- **R4.** A silent skip on an existing filename (`:378-380`). It is now detected and failed loudly (A8). Under S3b, EXTEND writes more files (about 18 instead of 1 at 50K rows), which raises the exposure the detector covers.
- **R5.** Vacuous retargeted tests. Mitigations: T-META, the per-test mutations M1–M4, and the T-R3 tripwire with a positive control.
- **R6.** Memory still grows linearly with the logical size of a single file: about 1× nbytes on the fast path and about 3–5× on unchunked EXTEND. The headroom estimate is roughly a 10 GB+ feather on the fast path at 2G, and about 2–3 GB on unchanged S3a EXTEND.
- **R7.** One native unit can overrun the deadline (the S2 residual). Arm 1 wall time records the Python-level `fs.open` read rate.
- **R8.** A Nautilus bump changes the native loop. T-PIN-1, T-PIN-2 and T-R4 (all `contract`) go red first.
- **RS-1 (A9, residual).** `_salvage_one_file` still materializes the whole recovered prefix as objects and runs `_drop_already_landed` over it (`quote_tape_salvage.py:258-259`). Coalescing removes only the per-message term.
- **RS-2 (residual).** `quote_tape_cli.py:36-37`, the manual converter, still calls native `convert_stream_to_data` (`read_all`). It is out of S3 scope.
- **RS-3 (residual, S3a).** The unfiltered full-range EXTEND dedupe query (Stage-0 F3 third site) stays unbounded until S3b.
- **Delegation invariant.** Every implementer brief restates: Nautilus is immutable; never weaken a safety, settlement or contract test; `allow_short` stays `False`; no operator-cap values; the NO-SEND firewall is untouched. Work is verified against the diff plus a gate re-run.

### r3: Arch §7, write-mismatch detector (replaces r2 §7)

**How `write_data` places files (verified, `parquet.py:320-355, 357-380`).**
- `write_data` sorts and groups objects by `identifier_function(obj) -> (type(obj).__name__, identifier)`, after unwrapping `CustomData` (:321-322). The identifier is:
  - `obj.id.value` for an `Instrument` (:328-329);
  - `str(obj.bar_type)` when the object has `bar_type` (:330-331);
  - `obj.instrument_id.value` when it has `instrument_id` (:332-333);
  - otherwise `None` (:336).
- Each group calls `_write_chunk(..., identifier=identifier)`, which writes to `self._make_path(data_cls=<group cls>, identifier=identifier)` (:370) under the filename `_timestamps_to_filename(start, end)`.
  - If that path already exists, it `print`s and returns (:378-380). That is the silent skip.
- `_make_path` applies `urisafe_identifier` itself (:2476-2477). The detector must therefore pass the **raw** identifier string (`instrument_id.value`, `str(bar_type)`), **never** the urisafe form, which would be encoded twice.
- **Flat case.** When the identifier is `None`, `_make_path(data_cls, None)` is the type root `…/data/<class_to_filename>` (:2470-2479), and the file is written directly into it.
  - For every EXTEND type today (`InstrumentStatus`, the tick types, `OrderBookDepth10`), objects carry `instrument_id`. `write_data` therefore **always** writes per-instrument directories, even when the partial slice was a flat native file.
  - That mixed layout is already pinned by `TestTheMixedCatalogLayoutIsPinned`. The flat branch exists for identifier-less data only.

**Detector (`quote_tape_salvage.py`).**
- **Helper.** A private helper `_write_data_group(obj) -> tuple[type, str | None]` mirrors `parquet.py:320-339` exactly: it unwraps `CustomData`, then returns `(type(obj), identifier)` using the same four-branch rule. Its docstring cites those lines.
- **Directories.** `dirs = {write_target._make_path(data_cls=cls, identifier=ident) for cls, ident in {_write_data_group(o) for o in fresh}}`.
- **Listing.** `_parquet_set(d) = set(write_target.fs.glob(f"{d}/*.parquet")) if write_target.fs.exists(d) else set()`.
  - This is **depth-1 only**. For the flat case (`d` = type root) it excludes identifier subdirectories. For a per-instrument `d` it is exactly the directory `_write_chunk` writes into.
- **Before and after.** Compute `before = ⋃ _parquet_set(d)`, call `write_data(fresh, skip_disjoint_check=True)`, then compute `after` the same way.
- **Count.** `written = Σ pq.read_metadata(f, filesystem=write_target.fs).num_rows for f in after − before`.
- **Raise.** If `written != len(fresh)`, raise `ExtendWriteMismatch(ValueError)` with the message `f"extend write mismatch for {class_to_filename(data_cls)}: expected {len(fresh)} row(s), landed {written} across {len(dirs)} dir(s)"`.
  - The message never contains "non-disjoint", an instrument id or a value.
- **Cost.** Two depth-1 globs per touched directory, plus footer-only reads of the new files. This replaces r2's type-root `find`, whose cost grew with every instrument of the type.

**Single-writer assumption (stated; verified that no lock exists).**
- `quote_tape_ingest_cli` takes **no** flock. The only `fcntl.flock` users in `src/breezy` are `persistence/catalog.py`, `persistence/archive_cache.py`, `runtime/submit_intent.py` and `runtime/trade_supervisor.py`.
- The unit is deliberately **not** behind the studies flock (`breezy-quote-tape-ingest.service:54-62`, T6/L-20).
- Serialization rests on systemd: the unit is a timer-started `Type=oneshot`, and systemd never runs two instances of one unit at once, because a start request while it is activating joins the running job.
- The only guard against a concurrent **hand-run** is the unit comment at :84-86 (L-50).
- Other code paths that write through `default_convert` target a separate catalog: `scripts/analysis/run_weather_strategy_backtests.py:1312` uses `target=work`. The manual `quote_tape_cli` (RS-2) can collide only if an operator hand-runs it, which breaks L-50.
- **Behaviour if the assumption is violated.** A foreign new file in a scoped directory inflates `written`, and the result is a loud **false-positive** `failed` (the safe direction). A foreign file could hide a real skip only if its row count exactly equalled the missing rows. That is accepted as negligible.
- **Not proposed:** adding a flock. It is out of S3 scope.

**Recovery for a persistent mismatch. Chosen: loud `failed`, file unmarked, reason-coded log, manual triage.**
- **Per-file path:** see Arch §3 (r3). The file is counted `failed`, left unmarked, and logged with `[reason=extend_write_mismatch]`.
- **Per-type path:** `_extend_overlapping_stream` → the existing `ValueError` → `failed` mapping (cli:1202-1207). The type marker is not written.
- **Exit and alert:** the run exits 3 (`EXIT_CONVERSION_FAILED`), so `OnFailure` alerts through `breezy-study-failed@`.
- **Self-healing case.** A rerun after a crash cannot mismatch. Rows that already landed, including the rows in a same-named file from the crashed run, come back from the dedupe query and are dropped before `write_data`.
  - A mismatch that **persists** across runs therefore means a genuine foreign file holds `write_data`'s exact filename with rows that are not the fresh rows. It alerts on every run until triaged.
  - That repeated alert is accepted as the signal.
- **Automatic quarantine: rejected.** The existing quarantine lives in the CLI, where salvage defers to it (`quote_tape_salvage.py:3-10`). It is keyed to a **preflight TRUNCATED instance** and refuses full conversion for the whole instance.
  - Reusing it would (a) falsely label an intact instance as truncated, (b) halt that instance's other types, and (c) still leave the collision unresolved.
  - Any automatic resolution (renaming or deleting the colliding parquet) is a rewrite, which EXTEND's contract forbids (cli:772: "does not rewrite an existing filename").
- **Residual.** Triage is manual. Compare the per-instrument directories of the failed type against the fresh `[min, max]` `ts_init` interval of the failing file; the colliding file carries that filename.
