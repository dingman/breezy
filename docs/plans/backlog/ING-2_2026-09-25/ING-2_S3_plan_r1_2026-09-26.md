# ING-2 S3: bounded ingest memory via a coalesced streaming read (plan r1, 2026-09-26; UNDER PEER REVIEW)

**Evidence.** See `ING-2_S3_stage0_findings_2026-09-26.md`. F3 dominates: the 698 MB file holds 891,170 one-row IPC messages, and native `read_all()` peaks at ~5.87 GB. F4 plateaus and is bounded.

## Acceptance criteria
- **AC-S3-1 (peak memory).** Take one synthetic feather written by the real writer, one row per message, N=200K. Push it through each of the three paths (fast/native, per-file, EXTEND). Each path's peak `ru_maxrss` in a child process must be ≤25% of a `_read_feather_file` control. Doubling N must grow the peak by no more than 2× the growth in `table.nbytes`, plus 32 MiB.
- **AC-S3-2 (chunk size).** No call to `_handle_table_nautilus` or `write_fresh_capture_rows` receives more than `EXTEND_CHUNK_ROWS` rows, except for an extension to cover a run of equal ts_init. The dedupe window per chunk is that chunk's own [lo,hi].
- **AC-S3-3 (layout unchanged).**
  - The fast and per-file paths produce the same parquet filenames and the same row set as today.
  - EXTEND produces the same row set in the same order.
  - The existing EXTEND tests and `TestTheMixedCatalogLayoutIsPinned` stay green.
- **AC-S3-4 (invalid streams).** A stream that goes invalid mid-read returns `None` (native parity, `parquet.py:2799`), never a partial prefix.
- **AC-S3-5 (production check, after merge).** On a scratch copy of the 698 MB file, both the fast path and EXTEND pass under `MemoryMax=4G -p MemorySwapMax=0`.
- **AC1 (F4) is demoted.** The plateau is bounded, and pool `bytes_allocated` is 0, so `release_unused` would have no effect.

## Trade-offs
- **Writer-side batching: REJECTED.** No native option exists. `StreamingFeatherWriter.write` serializes each object with `serialize_batch([obj])` and writes it with `write_table` (`writer.py:259,265`). `flush_interval_ms` only controls when to flush. `StreamingConfig` has no batch field.
- **Subclassing the catalog to override `_read_feather_file`: REJECTED.** That changes native behaviour silently and hides the base-class monkeypatch tests.
- **One parquet per chunk on the native path: REJECTED.** It would be refused as non-disjoint (closed intervals, `parquet.py:3006`), and it would change the file layout.
- **CHOSEN.** Coalesce batches while reading. Keep one native `_convert_feather_table_to_parquet` per feather. Chunk at the object level for EXTEND only.
- **Residual.** Memory still scales with the logical size of the largest file (~98 MB today). Option D (a streaming parquet writer) is held in reserve.

## Architecture
1. **`read_feather_coalesced(path, *, coalesce_rows=COALESCE_ROWS=8192)`.**
   - Open with `pa.OSFile` and `ipc.open_stream`, then call `read_next_batch()` in a loop.
   - Every `coalesce_rows` rows, build `Table.from_batches(group).combine_chunks()` and drop the group.
   - Return `Table.from_batches(coalesced, schema=reader.schema)`. The schema metadata must survive, because `_identifier_from_table_or_path` reads it.
   - `ArrowInvalid` or `OSError` returns `None`.
2. **Fast path, `default_convert` (:729-738).** A Breezy loop mirrors `parquet.py:2638-2654`: native `_list_feather_data_files` → `read_feather_coalesced` → native `_convert_feather_table_to_parquet` (native defaults). A non-disjoint `ValueError` still goes to EXTEND. The per-file path at :1295-1328 already works this way, so there is precedent.
3. **Per-file path.** Replace `_read_feather_file` (:1295) with `read_feather_coalesced`. The EXTEND fallback (:1343-1344) calls `_extend_table_chunked`.
4. **`_extend_table_chunked(catalog, write_target, data_cls, table) -> (written, streamed)`.**
   - Apply `_apply_stream_conversion_transforms` ONCE; it stable-sorts by ts_init.
   - Slice into `EXTEND_CHUNK_ROWS=50_000`. Advance each cut past any run of equal ts_init.
   - For each chunk: `_handle_table_nautilus`, then `write_fresh_capture_rows`.
   - Sorting first keeps each chunk's window narrow. The tie rule makes the result independent of chunk size and equal to the unchunked result.
5. **`_extend_overlapping_stream` (:784-791).** Use coalesced + chunked.
6. **Salvage `_scan_stream(collect=True)` (`feather_preflight.py:346-352`).** Coalesce via the shared helper, keeping prefix semantics.

## Phase 0 (gate, before any wiring)
Run a scratch probe of `read_feather_coalesced` on a copy of the 698 MB file under `MemoryMax=2G`, in a quiet window. If it fails, try a smaller `COALESCE_ROWS`, then `MALLOC_ARENA_MAX`.

## Risks
- **R1.** The mechanism is not yet isolated: decode buffers vs table chunks vs glibc arenas. Phase 0 is the gate.
- **R2.** Ordering: sort once, stably.
- **R3.** Chunk-boundary duplicates: the tie-extension rule prevents them; T8a pins it.
- **R4.** EXTEND writes more parquet files (~18 instead of 1). An exact filename collision is a pre-existing risk; pin the no-overwrite behaviour.
- **R5.** Migrating ~10 monkeypatch sites risks vacuous tests.
- **R6.** Memory still grows linearly with single-file size. The headroom is roughly a 10 GB+ feather at 4G.
- **R7.** One native unit can overrun the deadline (the S2 residual).

**Confidence.**
- HIGH: there is no native batch option.
- HIGH: the dedup and ordering analysis.
- MED-HIGH: coalescing brings the peak down to about the logical size (Phase 0 decides).
- MED: the constants.
