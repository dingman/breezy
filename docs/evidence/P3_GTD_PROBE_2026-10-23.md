## PASS conditions

The plan PASS line requires all of: echo within 1 s of G; NEW at the confirm read, the mid-rest read and the G-30 s read; `ORDER_STATE_EXPIRED` at the read issued in [G+55 s, G+65 s]; no fill; the final open-orders list empty.

The JSON records step ops, HTTP statuses and response key names. It does not record per-read state values or timestamps. The per-read states are implied by the horizon path in `scripts/venue/polymarket_us_maker_positive_control.py` (`_horizon_sequence`, `_horizon_confirm`, `_horizon_read_at`, `_horizon_expiry_read`, `_judge_echo`). A later attempt is recorded only when the previous read is retried. A null state is retried. A fill or other terminal state at confirm, mid or G-30 sets P3 FAIL (EARLY) and stops the run. A single attempt of each read (`get_B_confirm_1`, `get_mid_1`, `get_g_minus_30_1`, `get_g_plus_60_1`) reaching verdict PASS is only possible if confirm, mid and G-30 read NEW, the echo passed `_judge_echo` within 1 s, and the G+60 read was issued inside [G+55 s, G+65 s] and read `ORDER_STATE_EXPIRED`.

| Condition | Evidence |
|---|---|
| Echo within 1 s of G | After the confirm read returns NEW, `_judge_echo` requires `gtd_echoed`: time-in-force good-till-date, and the absolute gap between the echoed `goodTillTime` and the sent G at most 1 s. A larger gap sets P3 FAIL and raises CLAMPED. Anything else that is not an echo raises `ECHO_NOT_CONFIRMED`. Neither happened: mid, G-30 and G+60 reads exist, `verdicts.P3` is PASS, and `failure` is null. `echo_minus_tc_ns` 14398850221624 = 14398.85 s is written on that success path (echo minus create time). It is 14,400 s minus about 1.15 s, consistent with G set before post plus about 1.15 s create latency. |
| NEW at the confirm read | Only `get_B_confirm_1`, HTTP 200. `_horizon_confirm` sleeps 1 s, then polls. The first non-null state has to be NEW for the sequence to continue. |
| NEW at the mid-rest read | Only `get_mid_1`, HTTP 200. Mid is one read (`retries` 0) at create time plus half of 14,400 s. The sequence raises `MID_NOT_NEW` unless that state is NEW. |
| NEW at the G-30 s read | Only `get_g_minus_30_1`, HTTP 200. Two retries were available and unused. The sequence raises `G_MINUS_30_NOT_NEW` unless that state is NEW. |
| `ORDER_STATE_EXPIRED` inside [G+55 s, G+65 s] | Only `get_g_plus_60_1`, HTTP 200. `_horizon_expiry_read` issues the GET only while now is inside [G+55 s, G+65 s]. A read outside that window is not recorded and does not count. P3 PASS is assigned only when that read is `ORDER_STATE_EXPIRED`. NEW at that read is FAIL LATE and cancels by id. Cancels stayed 0, so LATE did not run. Any other non-fill state raises `G_PLUS_60_NOT_EXPIRED`. |
| No fill | `fill_detected` false. A fill on any horizon read raises `ORDER_FILLED`. Horizon `document()` then sets outcome INVALID, not PASS. |
| Final open-orders list empty | `final_clean_check` HTTP 200. `final_account_clean` is true only when that body has zero open order ids. It is true here. `final_get_B` HTTP 200 is the follow-up own-order read. Cleanup `cancelled`, `errors`, `left_to_gtd` and `leftover` are all empty. |
